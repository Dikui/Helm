# 调度者在对齐中也用关卡提问，关卡可多选

一般关卡本身就有选项按钮、自由回答、收件箱提醒和回答后唤醒，但原先运行层只许执行中提出，提示词也限定在五种必须停下来问的情形；对齐中调度者只能在消息里提问，用户要自己打字，问题也不进收件箱。2026-10-30 用户决定（按 Thariq 的 Claude Code 理念：需要用户拍板时给结构化提问）：对齐中和执行中都能用 `propose-gate` 提问；需要用户拍板时就用关卡，五种情形保留为必须停下来问的情况。

关卡加 `multiSelect`。多选回答按选项顺序每行一项，补充说明放在最后一行，仍是一条文本决定，任务库和调度者读法不变。对齐页保留已决定的问答，工作说明确认关卡仍是固定的那一个，不受影响。

## Considered Options

- **对齐中只用消息提问**：没有选项按钮，用户要自己打字；问题不进收件箱，回答也不单独唤醒。
- **多选回答存成数组**：要改关卡表、事件和所有读取方；一行一项的文本对调度者同样好读，自由回答也能放进同一字段。
