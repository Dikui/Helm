# 驱动按能力声明接入，配置加载由 Agent 的开关决定

> 2026-11-03：硬约束中的“只写本次运行目录”和“凭据禁读”已被 [ADR 0026](0026-agents-run-without-sandbox.md) 取代，Agent 改为无沙箱运行；其余规则继续适用。

接入 Claude、Codex、Grok、DeepSeek 后，每家驱动都积累了一套零散策略：按"角色 × 是否只读 × 计费方式"写死加载哪些用户配置（ADR 0005、0014，且 0014 只覆盖了 Claude），续跑只认会报告上下文占用的驱动，Grok、DeepSeek 写死只能当执行者。用户 2026-11-01 要求通用：再接一家 CLI 时不必翻历史 ADR 逐个补漏。决定 Helm 对 CLI 只做三类事，其余一律用 CLI 默认：**硬约束**（只写本次运行目录、不推送、凭据禁读、不派生 Helm 管不到的子进程），每家各自实现；**省 token**（调度者不加载用户配置、调度者续跑、精简调度者规则）；**不污染个人环境**（环境变量白名单、按会话关闭自动记忆）。每个驱动声明能力：能否干净启动、能否续接会话、是否报告上下文占用、能否当调度者、自动记忆如何关闭；运行层只按声明决策。续跑因此改为：能续接就续，报告占用的按 ADR 0017 的阈值换会话，不报告的连续续跑 10 轮后换会话。

用户配置是否进入会话由每个 Agent 的"加载全局配置"开关决定，调度者默认关、执行者默认开，已有 Agent 升级时按角色补默认值。2026-11-01 查明 Codex 0.165 app-server、Grok 1.0.70、dsh 0.2.1-rc.2 都没有在保留现有登录的前提下跳过用户配置的启动方式，三家声明不能干净启动，设置页把开关置灰并显示原因，而不是假装关掉。Codex 的 ChatGPT 连接器和远程插件按 ADR 0005 补记关闭，属于上游问题的绕过，不在契约内。

## Considered Options

- **继续按驱动名和角色写死规则**（原状）：每接一家都要重新决定一遍，规则散落在多份 ADR 里，用户读完认为"太复杂"。
- **为隔离换假 HOME 或复制凭据**：能让三家也干净启动，但执行者要用的 git 配置、ssh、`gh` 登录会失效，Codex 刷新令牌会让副本失效（ADR 0004 已否决）。
