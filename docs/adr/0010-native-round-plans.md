# 本轮计划沿用 Agent 原生工具，作为输出快照保存

v2 的本轮引导卡需要显示待做步骤和总数。2026-10-27 用户决定读取 Claude 的 TodoWrite、Codex 的 turn/plan/updated 和 ACP 的 plan 更新，不再发明调度者协议。驱动将其归一为 `DriverEvent { type: 'plan', step, entries: [{ content, status }] }`，状态为 pending、in_progress、completed。每条事件都是完整替换快照，空数组表示清空；原生消息仍记录在输出中。

计划和其他驱动事件一起持久化到轮次 / 派单输出，沿用现有单调递增步骤号、分页、压缩、导出及删除流程。list-rounds 从运行轮次的最新 plan 事件返回 currentPlan，没有则为空。计划不进入卡片状态表，不是卡片图，不参与调度或完成判定；界面根据计划计算总数，原始执行步骤可另行展开。

## Considered Options

- **新增 Helm 计划操作或要求 Agent 输出特殊文本**：会增加三种驱动都已有的协议之外的约定，用户明确要求不用。
- **从已发生的工具调用推断计划**：无法知道尚未发生的步骤和总数，容易把原始输出序号当成本轮计划进度。
- **单独建计划状态表**：需要同步和清理额外状态；现有输出已保存完整快照，本轮计划只用于展示，直接读取最新快照即可。

## 撤回与轮次领取的边界

消息正文仍不可变。新迁移只增加 withdrawn_at；撤回删除对应 wake_queue 项并追加 message-withdrawn 事件，与资格检查处于同一个 BEGIN IMMEDIATE 事务。轮次的事件选择和 event_ids 写入也放在同一个写事务里。任何历史轮次的 event_ids 已包含的消息（包括失败或中止轮次）均视为已领取，返回 MESSAGE_CLAIMED，不允许撤回；失败重投仍沿用原有队列机制。这样撤回与领取竞争时只能有一个胜出，不会让已经投递的内容在历史里被误标为未投递。

撤回消息保留在对话和导出记录中并标记撤回，后续启动简报的 newEvents 不再把其 message-sent 作为新消息投递。已有领取后失败的消息即使仍显示在等待队列，撤回也会返回明确的已领取原因。
