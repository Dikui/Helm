# 运行层给每个 Agent 分配临时数据目录

Helm 原样继承宿主的 `TMPDIR`，提示词只让执行者把中间文件放系统临时目录或结束前删掉。实际上 Agent 常把下载、解包、回放采集、索引和构建中间产物写进卡片副本（随后被运行层提交进卡片分支）、主目录或项目目录；写到系统临时目录的也没人清理，大数据回灌时可达几十 GB。用户决定由运行层分配并负责清理一个临时数据目录，`TMPDIR`、`TMP`、`TEMP` 指向它。

- 执行者按卡片分配 `<数据目录>/tmp/<卡片>/`：同卡的执行派单和验收派单共用，返工可直接复用上次的大文件。卡片完成或取消时删除，走卡片副本 / 临时目录的清理入口；工作完成、取消或删除时，随调度者目录一并删除这项工作所有卡片的目录，包括被跳过或未完成的卡片。
- 调度者按工作分配 `<数据目录>/tmp/<工作>/`，工作完成、取消或删除时随调度者目录删除。
- 卡片和工作的 id 都是 UUID，同放一层不冲突；不加中间层级，保持路径短，避免 macOS 上在临时目录里建 Unix socket 超出路径长度上限。
- 三个变量在运行层组装环境时统一设置，覆盖宿主值，所有驱动都生效；与其他运行层变量一样，项目环境变量不能覆盖。
- `<数据目录>/tmp/` 完全归 Helm：启动对账删除不属于活动卡片或活动工作的条目，符号链接只删链接本身。
- 不计入输出总量，不设大小上限。提示词要求执行者把中间文件和临时数据放 `$TMPDIR`，不要写到卡片副本、主目录、项目目录或其他位置。

## 2026-11-13 补充：位置可配置

用户要求根路径可配置，以便把大体积的临时数据放到更快或更大的磁盘上。设置页「运行」里填一个绝对路径，Helm 在其下建 `helm-tmp/` 并只管理这个子目录，启动对账也只清理它，不会动该位置原有的文件；留空恢复默认的 `<数据目录>/tmp/`。修改时删除旧位置下 Helm 管理的临时数据，不迁移：卡片之后的派单在新位置重新生成。有运行中的派单或调度轮次时拒绝修改，避免删掉正在使用的目录；新旧位置互相包含时也拒绝，避免删除旧目录时连带删掉新目录。

## 与 ADR 0026 的区别

ADR 0026 否决过"每次派单一个私有临时目录，`TMPDIR` 指向它"，那是作为沙箱的替代：想靠它让 Agent 在写入受限时仍能写临时文件，结论是缓存、Docker、仓库外构建目录仍要逐个补。本决定的目的不同，是给临时数据一个默认去处并由运行层清理：不恢复任何写入限制，Agent 仍可写本机任何位置；目录按卡片而非按派单分配，以便返工和验收复用。

## Consequences

- 中间文件不再被提交进卡片分支，卡片或工作结束后自动删除；写到 `$TMPDIR` 之外的仍不会被清理。
- 同一卡片的并发验收派单共用一个目录，同名文件可能互相覆盖；需要隔离时 Agent 应在其中再建子目录（如 `mktemp -d`）。
- 卡片在结束前留下的大文件会一直占用磁盘，不计入输出总量提醒。
