# 调度者按调度轮次运行，不用长时会话

调度者要从对齐一直推进到审核，中间可能隔几天。我们不让它在一条 CLI 会话里常驻，而是每次被事件唤醒都新开一个会话（调度轮次）：运行层拼一份启动简报（工作说明、卡片图摘要、未决关卡、调度笔记、新事件、最近 20 条对话），调度者处理完这批事件就退出。跨轮次的记忆只在任务库和调度者自己改写的调度笔记里。这样上下文不会随工作变长而涨满，平常的唤醒和崩溃后接续走同一条路径；代价是每轮重读简报、多花额度和几秒冷启动。详见调度者生命周期（`.scratch/helm-v1/issues/06-coordinator-lifecycle.md`，仅本地）。

## Considered Options

- **长时会话 + 快满时交接**（01 原先的选择）：上下文会涨满，需要另做"读占用、关压缩、写交接说明、换会话"一整套机制，而各家驱动能力不一（Codex 关不掉自动压缩，Grok 读不到每轮占用），见 [context-usage-and-compaction.md](../research/context-usage-and-compaction.md)。
- **混合**（对齐阶段续跑会话，之后任务型）：对齐时不必反复看代码，但有两条路径。留作退路：14 实测发现任务型跨轮次失忆或对齐体验太差时改用。
