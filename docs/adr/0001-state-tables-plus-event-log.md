# 任务库用当前状态表加事件表，不做纯事件溯源

任务库既要给调度者的工具和界面读"现在是什么状态"，又要给回放和追溯读"发生过什么"。我们让每次操作在同一个 SQLite 事务里改写当前状态行、追加一条事件：读状态直接查表，回放直接按序读事件表，两者不会不一致。状态行只由运行层根据操作和进程信号改写，模型不直接写。

## Considered Options

- **纯事件溯源**（只存事件，状态靠重放或投影得出）：每次查询都要重放或维护投影，对个人使用的单机工具太重。
- **只有状态表加文本日志**：日志不是结构化数据，做不到"任何问题都能追溯到具体的 agent 和步骤"（地图成功标准 5）。
- **持久化执行库**（DBOS、Temporal 一类，记下多步骤代码每一步的结果，崩溃后重放到断点）：运行层没有可重放的长流程，编排在调度者那里，运行层每个操作只是一个短事务加一个外部动作；耗时的执行者进程也设不了断点，恢复终究靠续跑对话。改为外部动作先做且可重做、成功后再写库，helmd 启动时对账（见 `.scratch/helm-v1/issues/11-persistence-and-recovery.md`，仅本地）。

## 删除工作

用户删除一项已结束的工作时，它的状态行和事件一起删掉，只留一条 `work-deleted` 事件记下删过什么。事件表负责追溯还存在的工作，不负责永久留档；要留档就先导出。
