# 去掉模板，Agent 由用户创建并存在数据目录

原来的 Agent 模板放在仓库的 `templates/` 里，设置页保存也写进这个目录。用户改过的配置因此和 Helm 的代码绑在一起：更新或重装 Helm 会覆盖或冲突。用户 2026-10-24 决定不要模板：Agent 都由用户在「Agent 集群」里按需创建，存在 `~/.helm/agents/<id>/`（`config.json`、`prompt.md`、可选 `skills/`），Helm 更新不碰这里。

原来模板的 `prompt.md` 主要是调度者和执行者的工作规则，各驱动之间只差几个字。这部分改为按角色内置在 `src/prompts.ts`（ADR 0008 已改为存进数据目录、可在设置页改），每个 Agent 自动带上；Agent 的 `prompt.md` 变成可选的附加要求，排在内置规则之后、运行约定之前。这样用户新建 Agent 不必自己写调度规则，规则改进也随 Helm 更新生效。

已有任务库在首次启动时一次性迁移：`~/.helm/agents/` 不存在且任务库里已有工作时，按原来 6 个内置模板的设置生成同名 Agent（附加提示词为空），旧工作和派单引用的 id 仍然有效。全新安装不生成任何 Agent。之后启动不再迁移。

同时把代码、操作、事件和任务库列名里的"template"统一改成"agent"（例如 `list-agents`、`agent_id`、`round-agent-loaded`，API 计费的 `home` 值改为 `dedicated`），由一条迁移改写已有列名、事件和快照。

## Considered Options

- **模板留在仓库，用户 Agent 放数据目录，从模板新建**：概念多一层，用户还要分清"模板"和"Agent"；模板里真正有用的是工作规则，内置后模板只剩几个默认字段，不值得单独成为概念。
- **启动时把仓库模板复制到数据目录**：解决了覆盖，但用户删掉的会被补回来，内置规则的改进也到不了已复制的副本。
