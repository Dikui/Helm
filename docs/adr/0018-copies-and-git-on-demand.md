# 副本和 git 按需使用，由调度者按卡片判断

ADR 0012 让每项工作在创建时就开出工作分支和工作副本，但很多工作只是调研、分析，从头到尾不写代码；分析到一半才转开发的，创建时也没人知道要不要副本。用户 2026-10-30 决定副本和 git 都按需使用：调度者建卡时标明卡片只读还是写代码，第一次派出写代码的执行派单前，运行层才开出工作分支、工作副本和卡片副本；在这之前调度者在项目目录里只读运行。调研了 Claude Code、Codex、Cursor、Copilot、Zed 等，本地产品都是要写代码时才隔离，只读不建副本（调研笔记仅本地：`docs/research/work-copy-and-git.md`）。

规则：

- 卡片默认写代码，只读要调度者显式标记。只读卡片的执行派单不建卡片副本，在只读沙箱里运行：有工作副本时在工作副本，没有就在项目目录；完成时不合并。
- 项目不要求是 git 仓库。只有非 git 项目上第一次要派写代码的执行派单或验收派单时，运行层才生成决策关卡，请用户同意初始化 git；同意前这张卡片阻塞。初始提交包含现有文件：已有 `.gitignore` 就照它，没有就在同一个关卡里列出体积大或像密钥的路径，由用户确认忽略规则，`.gitignore` 和文件一起提交。不再用空提交当基线，否则副本是空的。
- git 项目的基准分支仍在创建工作时选，默认项目当前检出的分支；工作分支开出时取基准分支的最新提交。副本离不开 git，git 项目不一定有副本。
- 调度者的工作目录从项目目录换到工作副本的那一轮新开会话，与调度者 Agent 快照变化同样处理（ADR 0017），不跨目录续跑。
- 验收派单检查的提交：派过执行单的卡片取卡片分支末端，否则取工作分支末端，还没有工作分支时取基准分支的最新提交。
- 没有工作分支的工作，审核时没有差异；接受后直接完成，不进入待合入。
- 已有副本的旧工作照常使用，不删除也不补建。

代价：对齐阶段读的是用户当前目录，会随用户切分支、改文件而变，并行的几项工作看到的也是同一份即时状态；开副本时若项目目录检出的不是基准分支或有未提交改动，运行层在对话里提示，副本不带这些改动。

## Considered Options

- **创建工作时让用户选是否建副本**：用户创建时不知道后面要不要开发，分析到一半转开发时仍要另想办法。
- **确认工作说明时建副本**：改动最少，但调研类工作确认后派只读卡片，仍白占分支和副本。
- **调度者始终在项目目录运行**：执行阶段调度者要看工作分支上已合并的卡片成果，项目目录里没有。
- **非 git 项目让执行者直接在项目目录写**：并行卡片互相覆盖，审核没有差异，改坏了无法撤回。
- **需要时自动 `git init`，不问用户**：会在用户目录写 `.git`，调研的产品里没有不问就初始化的。
