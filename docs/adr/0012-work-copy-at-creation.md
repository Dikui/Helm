# 创建工作时就开出工作分支和工作副本，对齐阶段调度者只读副本

> 已被 [ADR 0018](0018-copies-and-git-on-demand.md) 取代：工作分支和工作副本改为第一次派出写代码的执行派单前才开出，对齐阶段调度者在项目目录只读运行。

原来工作分支和工作副本在确认工作说明时才开出，对齐阶段调度者直接只读项目目录，读到的是用户当时检出的分支和未提交改动，同一项目上并行的多项工作也就各自依赖用户目录当下的状态。用户 2026-10-28 决定创建工作时就开：新建表单选基准分支（默认项目当前检出的分支），创建即从它开出 `helm/<工作>` 和 `_work` 副本，对齐轮次的工作目录就是副本。对齐可能拖很久，所以确认工作说明时，工作分支若还没有自己的提交，就移到基准分支的最新提交；已有提交则不动。

代价：每项对齐中的工作都占一个分支和一份 worktree，取消对齐中的工作时连分支一起删除；旧的对齐中工作在下一调度轮次启动前补建副本。

## Considered Options

- **对齐时继续读项目目录**：读到的内容随用户切分支、改文件而变，工作说明可能基于用户没提交的代码。
