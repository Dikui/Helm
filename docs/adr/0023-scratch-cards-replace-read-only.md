# 去掉只读卡片，按是否需要项目代码选卡片副本或临时目录

只读卡片在工作副本或项目目录里运行，靠各家 CLI 的只读模式拦写入。实际用下来，Grok 1.0.70 的只读沙箱在 `/var/run/docker.sock` 是软链接的机器上（如 OrbStack）拒绝启动，Codex 只读时不能联网，同一张调研卡片换执行者能力就不同，还要四套只读实现。2026-11-01 调研主流编排器（Conductor、vibe-kanban、Claude Squad、Sculptor、Copilot、Cursor、Jules）发现它们都没有"只读任务"：任务在可丢弃的副本或环境里跑，只读只是 CLI 会话里的 Ask / Plan 模式。用户决定不做只读，但不是所有卡片都开副本，判断依据也不能是"会不会写"：卡片按"要不要读或改本项目代码"选运行位置。要，就在卡片副本里运行并合并；不要（联网调研、对比外部方案、起草），就在 Helm 数据目录下的临时目录里运行，可写可联网，文件存为派单成果，不碰 git、不合并，也不要求项目是 git 仓库。执行者因此只有一套可写权限。临时目录卡片的验收用一次性复制，验收开始后该卡又有执行派单结束则验收过期。已有只读卡片迁移为卡片副本。

## Considered Options

- **保留只读，各家 CLI 只读沙箱加派单后的 git 状态比对**：2026-11-01 实现过（比对 HEAD 和工作区指纹、记录违规），没有一家主流产品这样做，而且解决不了 Grok 起不来和 Codex 不能联网，随后删除。
- **所有卡片都开副本**：最接近主流，但纯联网调研也要建 worktree，非 git 项目还得先初始化 git，调研文件会混进审核差异。
- **按"会不会写"决定建不建副本**：建卡时猜不出执行者会不会写，本质上又回到只读卡片。

## 2026-11-06 补充：临时目录成果不设大小上限

每次执行派单结束都重新保存临时目录里的所有普通文件，不跨派单去重；符号链接只记录跳过说明。文件先异步复制并流式脱敏，全部成功后才一次写入成果记录和事件。复制失败时回收本次复制文件、记录未保存原因，派单出错；禁止完成卡片以保留原件，释放空间或删除文件后重新派单再完成，放弃文件则取消卡片。

代价是同卡返工会重复占用成果空间。成果计入默认 10 GB 的输出提醒阈值，超过只提醒、不拦截。20 MiB 仅是预览和附件上传上限，较大成果可流式下载；HTML 预览仍加载不到相对路径引用的文件，这类成果需下载相关文件、恢复目录结构后在本地打开。
