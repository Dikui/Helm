# 工作说明加"交付"，调度者按用户目标推进

工作说明原来分需求、边界、标准三部分，没有地方写成果放在哪里、用户从哪里使用，调度者往往在卡片全部完成后就交审核，用户拿到的东西却用不上。规则提示词还用固定次数停卡（返工两次不过就停），整体验收卡一律要建，标准写得过细时，调度者为了改检查命令也要重新起草说明。用户 2026-11-05 先在服务端改了代码和运行提示词，随后决定并入默认值。

- 工作说明改为需求、边界、验收、交付四部分。"标准"改名"验收"，字段仍叫 `criteria`；新增必填的 `deliverables`。Helm 还是 demo 版本，以准确为先，不为旧调用保留兼容：第 35 次迁移只为让旧数据库能打开，旧记录的交付是空字符串，界面不另加提示。
- 调度者对用户目标的整体达成负责：卡片说明和调度笔记保留用户目标、交付形式和使用入口，交审核前按交付入口核对成果。
- 在已有授权内补齐实现、纠正检查命令或细化判据时，不重新起草说明；改变目标、授权边界或用户要求的通过条件时才重新确认（关卡③）。
- 停卡不再看次数，而是看新证据和可检验的下一步：重复失败先诊断、改方法或换驱动，没有可行的授权内下一步，或达到用户给的预算 / 停止条件时，才停卡交付。
- 整体验收卡只在跨卡集成结果单卡查不到，或用户要求时才建。

## Consequences

- 每部分默认 1–3 条短句，具体命令和执行步骤写进卡片，不写进工作说明。
- 没有固定次数上限后，返工轮数可能变多；用户要控制成本，就在边界里写明预算或停止条件。
- 没建整体验收卡的工作，审核报告引用已有的检查证据，并写明覆盖了哪些标准。
- 执行者提示词不再写"测试只跑派单写明的命令"，测试范围交给派单内容决定。
