# 派单内部 Git 跳过项目钩子，固定五分钟超时

Helm 的自动提交和卡片合并只是内部记录。项目钩子失败会阻止自动提交，下次派单重置卡片副本时可能丢掉执行者的改动；钩子耗时或挂住也会阻塞同步 Git 所在的运行层（#30 第 6 项）。用户决定 `dispatchGit` 统一传入 `-c core.hooksPath=/dev/null`，并用命名常量设置固定五分钟超时，不增加设置项。超时诊断同时保留错误原因和已有 stderr。

## Consequences

- 项目钩子不再检查 Helm 的自动提交和卡片合并；执行者自己的提交、合入基准分支和推送仍运行项目钩子。
- `dispatchGit` 仍同步执行，挂住时 Helm 最多卡五分钟才进入错误处理；合并失败仍检查冲突并中止未完成的合并。
- alignment 的工作副本操作暂不调整，保留 `post-checkout` 失败后回滚并重试的现有路径和测试；这条独立路径仍可能被项目钩子阻塞。

## Considered Options

- **改成异步**：`completeCard` 从检查、合并到写任务库，现在依靠同步执行才不被其他请求打断。异步需要增加按工作排队的机制，本次不引入。
- **只在提交时跳过钩子**：卡片合并和派单创建副本仍会触发项目钩子，不能统一保护派单内部操作。
