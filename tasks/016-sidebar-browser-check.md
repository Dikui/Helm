# 任务 016：侧边栏整理浏览器检查（只检查，不改代码）

## 背景

任务 015 整理了侧边栏（只列项目并显示待处理数），把项目记忆、项目设置入口移到项目页，并在节点页加了面包屑与切换节点下拉（见 `tasks/015-sidebar-cleanup.md`、`evidence/015/report.md`）。本任务在真实浏览器中检查，并回归任务 014 的检查。

## 要做的内容

1. 启动静态服务：`python3 -m http.server <空闲端口> -d prototype`，不要用 8787。无头浏览器（Playwright 装在项目目录以外，或本机 Chrome headless），视口 1440×900，浅色。
2. 场景（截图保存到 `evidence/016/`，文件名以场景编号开头）：
   - S01 收件箱页的侧边栏：四个分区（收件箱、项目、知识、记录）；项目下只有项目名与待处理数，没有节点；断言各项目数字之和加上不归属项目的条目数等于收件箱总数
   - S02 进入项目 A 项目页、其节点页、项目记忆、项目设置：侧边栏都高亮项目 A（各截一张或合并截图）
   - S03 项目记忆与项目设置从项目页右上角进入，页面面包屑可返回项目页
   - S04 节点页：面包屑"项目名 / 节点名"，点击项目名回到项目页
   - S05 切换节点下拉：展开后（或读取选项）包含同项目全部节点并带状态文字，当前节点已选；选择另一个节点后打开其「规格与结果」页签
   - S06 在「技术可行性」判定无法判定的测试并验收后，侧边栏项目 A 的待处理数减少（截前后）
   - S07 处理项目 C 的阻塞型发现生成新节点后，新节点出现在切换节点下拉中
   - S08 新建项目：创建一个项目后出现在侧边栏项目列表中
   - S09 键盘：Tab 到切换节点下拉，用键盘选择另一个节点并打开
   - S10 深色模式：收件箱页侧边栏、节点页面包屑与下拉
   - S11 窄屏 375×812：侧边栏、节点页面包屑与下拉无溢出，页面无横向滚动（`document.documentElement.scrollWidth <= innerWidth`）
3. 每个场景用 DOM 断言，结果保存到 `evidence/016/assertions.txt`，每行 `PASS/FAIL Sxx 描述`。S10、S11 用 `getComputedStyle` 抽查侧边栏项目项（普通 / 高亮）、待处理数字、面包屑、下拉的对比度 ≥ 4.5:1。
4. **回归**：复制 `evidence/014/browser-check.mjs` 到 `evidence/016/regression-014/` 下运行（不改原脚本和原证据）；对每条失败判断是预期变更（例如旧脚本通过侧边栏节点项导航）还是回归问题；预期变更时，用新的导航方式补测对应行为并记录结果。
5. 控制台 error、warning、未捕获异常保存到 `evidence/016/console.txt`，没有写"无"。检查脚本保存为 `evidence/016/browser-check.mjs`。
