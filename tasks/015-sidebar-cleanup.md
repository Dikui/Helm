# 任务 015：整理左侧边栏

## 背景

用户审查原型后的意见：左侧边栏把每个项目的所有节点都列出来，没有必要（节点在项目页的流程图中已经清楚可见）。用户已确认：项目旁显示待处理数；节点页加节点切换下拉。

**先读：** `prototype/index.html` 中的 `renderSide()`、节点页顶部渲染（任务 013 的常驻顶部）、项目页右上角按钮；`evidence/013/report.md`。

## 要做的内容

只改 `prototype/index.html`。

### 1. 侧边栏结构

| 分区 | 内容 |
|---|---|
| 收件箱 | 不变，带待处理总数 |
| 项目 | 只列项目名（不列节点）；每个项目旁显示该项目在收件箱中的待处理数（为 0 时不显示数字）；当前所在项目（项目页或其节点页、项目记忆、项目设置）高亮；底部"新建项目"（原"全部项目 · 新建"入口保留其功能） |
| 知识 | 经验库、代理库、编排模板、模板 |
| 记录 | 决策记录 |

- 删除侧边栏中的节点列表、"查看项目流程"子项，以及按项目列出的"项目记忆"入口。
- 待处理数与收件箱各分组条目同源计算（同一个函数），保证侧边栏各项目之和等于收件箱中归属项目的条目数；不归属任何项目的条目（如代理提议、教训建议）只计入收件箱总数。数字旁要有可读文字（如 `aria-label="3 项待处理"`）。

### 2. 项目级页面入口

- 项目记忆、项目设置只从项目页右上角进入（按钮已存在，确认在三个项目中都可用）；这两个页面顶部有面包屑"项目名 / 项目记忆（或项目设置）"，可返回项目页。

### 3. 节点页面包屑与节点切换下拉

- 节点页顶部（常驻区）显示面包屑"项目名 / 节点名"，项目名可点击回到项目页。
- 面包屑旁加"切换节点"下拉：列出同一项目的全部节点（按项目流程分层顺序），每项显示节点名与状态文字；当前节点标为已选；选择后打开该节点（默认「规格与结果」页签）。由发现生成的新节点也要出现在下拉中。
- 下拉可用键盘操作（使用原生 `<select>` 或实现完整的 listbox 键盘交互，二选一，优先原生）。
- 窄屏（≤ 760px）下面包屑与下拉不溢出、不产生页面横向滚动；深色模式正常。

## 不要做的内容（边界）

- 只改 `prototype/index.html`；证据写入 `evidence/015/`；报告写到 `-o` 指定的文件。不改 `FEATURES.md`、`tasks/` 下已有文件、`evidence/001`–`014`。
- 不改变数据模型与业务行为；不改项目页与节点页其他内容；不做浏览器检查。

## 必须有的测试

`evidence/015/check.mjs`（只用 Node 内置模块，沿用 `evidence/013/check.mjs` 的做法）：

- T01 侧边栏只含四个分区与规定条目；不含任何节点名、"查看项目流程"、项目记忆入口
- T02 每个项目的待处理数等于收件箱中归属该项目的条目数；各项目之和 + 不归属项目的条目数 = 收件箱总数；为 0 时不显示数字；数字有可读文字
- T03 处理一条待办（如判定无法判定的测试并验收、回答提问）后，侧边栏对应项目的数字同步减少
- T04 当前项目高亮：在项目页、该项目的节点页、项目记忆、项目设置中都高亮正确项目
- T05 项目记忆、项目设置可从三个项目的项目页进入，并有可返回的面包屑
- T06 节点页面包屑正确，点击项目名回到项目页
- T07 切换节点下拉包含同项目全部节点（按分层顺序、带状态文字），当前节点已选；选择后打开目标节点的「规格与结果」页签；发现生成的新节点出现在下拉中
- T08 新建项目入口仍可用（创建后出现在侧边栏项目列表中）
