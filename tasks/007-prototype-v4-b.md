## 要做的内容

所有改动只在 `prototype/index.html` 中完成。保持单文件、零外部依赖、无构建步骤，界面文字使用中文。原型是**模拟**：编排不真正执行，用模拟数据和按钮驱动状态。

### 1. 节点主 agent 与执行编排（FEATURES §1.4–1.6）

- 节点详情新增「执行编排」卡片：模板名（如"批量清单"）、步骤图（步骤按顺序 / 并行排列）、每步的四态结果、花费；点击步骤可展开该步的输入摘要与结构化输出。
- 卡片中可查看计划（JSON 示意，标注"示意，非最终接口"）和执行前校验结果（5 条校验各显示通过 / 不通过）。
- 简单节点没有编排，卡片显示"本节点由主 agent 直接完成，未使用编排"。
- 主 agent 的唤起记录：开工、编排结束、步骤异常、预设决策点四种原因，写入时间线并标注原因。
- 上限新增"重新规划次数"，在信息带中和其他上限一样显示进度。
- 内置的模板列表（FEATURES §1.6 表格中的 15 个模式及 P0/P1/P2/后续标记）在一个"编排模板"页面中只读展示。

### 2. 四态结果（FEATURES §1.7）

- 状态：通过 / 失败 / 无法验证 / 未处理（附原因）。颜色与 v2 的通过 / 不通过 / 无法判定区分开，且不能只靠颜色区分，必须有文字。
- 批量清单类编排：每一项都有状态；验收报告中把失败、无法验证、未处理三类**单独列出**，不能只给总数。
- 规则：清单冻结后条目数不变；没有状态的条目不得出现。

### 3. 尝试记录（FEATURES §1.11）

- 把执行记录升级为尝试记录：每次尝试显示会话 ID（未知显示"未记录"）、快照分支名、编排计划版本、步骤结果汇总、结束原因（完成 / 验证失败 / 步骤异常 / 达到上限 / 无法判定 / 被中断 / 被取消）、花费。
- 每次尝试注明"下一次如何接上"：续接原会话 / 新会话带失败摘要 / 只重做失败与未处理项。
- 保留 v2 的"失败方法不得重复，除非有新理由"提示。

### 4. 发现转新节点（FEATURES §1.10）

- 节点可以有"发现"：问题描述、证据、位置、相关资料（文件路径、日志片段等）、是否阻塞本节点。
- 发现进入收件箱"发现"分组，显示 leader 的分流建议：忽略（写明理由）/ 并入已有节点 / 起草新节点。
- 批准"起草新节点"后：项目流程中出现新节点，其资料来源包含发现附带的资料，依赖关系按 leader 建议；阻塞型发现使原节点暂停并依赖新节点。
- 自主度中"发现转新节点"设为自动时，leader 起草后直接加入项目流程。

### 5. 项目指令与项目记忆（FEATURES §1.14）

- 新增"项目记忆"页面（每个项目一个，侧栏"知识"下可进入）：项目指令、设计决策（有效 / 已废弃，已废弃注明被哪一条取代）、约定、注意事项，每条显示来源和被哪些节点引用。
- 项目指令中的强制条目自动合并到该项目每个节点的边界中，显示 🔒 并标注来源"项目指令"。人可以增删项目指令。
- 设计决策由 leader 提议，进入收件箱"待确认的设计决策"，人确认后生效；注意事项由 leader 直接写入，人可以撤销。
- 废弃一条设计决策时不删除，标为已废弃并注明取代者。

### 6. 人工关卡与副作用状态（FEATURES §1.11、B13、B14）

- 至少一个编排包含人工关卡步骤：进入收件箱"人工关卡"，显示批准对象及其内容哈希（模拟值，标注"示意"）；批准后该步骤为通过，拒绝后为失败。
- 至少一个"副作用状态不明"示例（例如合并回执未知）：进入收件箱同名分组，人可选择"核对后标记已完成"或"标记未完成并重新执行"；任何一种都写入决策记录。此类决策不能设为自动。

### 7. 收件箱、自主度与模型配置

- 收件箱在 A 的 6 组基础上新增 4 组：发现、人工关卡、待确认的设计决策、副作用状态不明（共 10 组）。
- 自主度新增决策点：执行编排确认（默认自动）、发现转新节点、项目记忆·注意事项（默认自动）；始终由人：项目记忆·设计决策、副作用状态不明（FEATURES §4 表）。
- 代理配置中的模型分为"作为主 agent"和"作为编排步骤"两项；内置模板默认值按 FEATURES §5 表格。
- 项目预算：项目页显示项目预算与已用花费，节点详情显示本节点花费；数字为模拟值。

### 8. Demo 数据（FEATURES §7）

- 项目 A「市场调研」节点：**并行汇总**编排，多个来源并行检索 → 汇总，其中一支为"无法验证"并在验收报告中单独列出。保留它原有的"达到上限"场景，两者需协调（例如这次尝试因上限结束、编排中部分步骤未处理）。
- 项目 B「浏览器检查」节点：**批量清单**编排，第 2 次尝试的检查项使用 `evidence/002/recheck-1/assertions.txt` 中的真实条目（38 项，全部通过）；第 1 次尝试的结果使用 `evidence/002/assertions.txt`（31/34），3 项失败要逐项列出。条目文字可以缩写，但必须能对应到原文件的行；报告中给出对应关系。
- 项目 B「实现」节点：两次尝试按第 3 项的新结构展示。
- 至少一条"发现"示例：执行中发现与本节点无关的问题，由 leader 起草为新节点（内容可为模拟，但不得冒充真实记录，标注"示例"）。
- 至少一条项目指令、两条设计决策（其中一条已废弃）、一条注意事项。
