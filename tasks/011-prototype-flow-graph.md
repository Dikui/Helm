# 任务 011：项目流程改为有向图展示

## 背景

用户审查原型后的意见：节点之间的关系不够直观。当前项目页把节点按层排成卡片，依赖关系另起一行写成文字（如"需求澄清 → 技术可行性"），需要来回对照。要求改为真正的图。

**先读：** `prototype/index.html` 中的 `renderProject()`、`flowStages()` 及相关样式；`evidence/009/report.md`（当前数据结构、项目 C）；`FEATURES.md` §1.2、§1.9、§1.10、§6。

## 要做的内容

只改 `prototype/index.html`，单文件、零外部依赖，用内联 SVG 自行绘制，不引入任何库。

1. **项目页的项目流程图**（项目 A、B、C 及新建项目都适用）：
   - 节点为方块，显示节点名、状态标签（文字 + 颜色，不能只靠颜色）、执行代理名；依赖为带箭头的连线。
   - 布局按依赖分层，从左到右；同层（并行）节点上下排列，汇合与分叉清晰可见；连线不得穿过其他节点，不得与节点文字重叠。
   - 条件分支：条件文字（若可行 / 若不可行等）标在对应连线旁。
   - 退回过的依赖用不同线型（如虚线）并标"退回"；由发现生成的节点和其连线用另一种标记（如虚线边框并标"发现"）。
   - 点击节点进入节点详情；节点可用键盘聚焦并用 Enter 打开（无障碍）。
   - 悬停或聚焦节点时，高亮该节点的上下游连线，其余连线变淡。
   - 图下方保留一行图例：状态颜色、退回线型、发现标记、条件分支。
   - 删除原来的"依赖关系文字行"；但为屏幕阅读器保留一份不可见的依赖列表（如 `aria-label` 或视觉隐藏的列表）。
2. **节点详情页**：增加一张小图，只画本节点及其直接上游、直接下游各一层，点击可跳转。
3. **窄屏（≤ 760px）**：图改为从上到下的竖向布局，宽度适应屏幕，不出现横向滚动；节点文字不被挤成逐字换行。
4. **深色模式**：连线、节点、文字、图例颜色使用 CSS 变量，深色模式块同步定义。
5. 项目流程编辑（增删节点、改依赖）后图要重新布局；发现转新节点后新节点出现在图中。

## 不要做的内容（边界）

- 只改 `prototype/index.html`；证据写入 `evidence/011/`；报告写到 `-o` 指定的文件。不改 `FEATURES.md`、`tasks/` 下已有文件、`evidence/001`–`010`。
- 不改变数据模型和其他页面的行为；不做浏览器检查（会单独安排）。
- 不引入外部库、CDN、字体。

## 必须有的测试

`evidence/011/check.mjs`（只用 Node 内置模块，沿用 `evidence/009/check.mjs` 的做法）：

- T01 三个项目的项目页都渲染出 SVG 图：节点数、连线数分别等于项目流程中的节点数与依赖数；每条连线带箭头
- T02 布局：每条连线的起点层级小于终点层级；同层节点的方块不重叠（用计算出的坐标检查矩形不相交）；连线路径不穿过非端点节点的矩形（对折线 / 曲线采样检查）
- T03 条件分支连线旁有条件文字；退回过的连线与发现生成的节点有各自的标记
- T04 节点可点击进入详情，且有 `tabindex` 与键盘打开处理
- T05 原来的依赖文字行已移除；存在供屏幕阅读器使用的依赖描述，内容覆盖全部依赖
- T06 节点详情小图只包含本节点、直接上游、直接下游
- T07 编辑项目流程（新增节点并设依赖）后图重新布局并包含新节点；发现转新节点后图中出现新节点
- T08 窄屏布局函数输出竖向布局（层沿 y 方向递增），且总宽度不超过给定的 375px 视口内容宽度
- T09 状态标签在图中有文字，不只靠颜色
