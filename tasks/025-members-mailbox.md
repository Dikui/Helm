# 任务 025：原型 v7 第 3 批：成员、派单与信箱

报告 `tasks/025-report.md` 的第一行写 `session-id: <你的会话 ID>`。

## 背景

原型正在分 5 批改到 v7（`FEATURES.md` 第 13 节）。第 1 批做了数据模型与看板，第 2 批做了项目对话、收件箱、你的要求与决策撤销。本批做**谁在干活、他们之间怎么沟通**：成员与派单、成员看板、通知、卡片状态行、信箱与消息时间线、暂停与恢复。

v7 的调度模型仿照 Orca（`FEATURES.md` 3.1）：项目负责人是协调者；**派单**是把一张卡交给一个会话做一次，一次派单就是一次尝试；成员每次派单**恰好发一次完成报告**；消息按轮投递。

本任务涉及界面，对应的浏览器检查是**任务 026**，026 通过后本任务才算完成。

## 要做的内容

### 1. 数据：成员、派单、消息
- **派单**：卡片、会话、代理与模型、工作区说明、开始和结束时间、结果（成功 / 失败 / 状态不明 / 进行中）、完成报告（结果、摘要、改了哪些文件）、心跳时间、花费。v4 留下的"尝试"数据迁成派单（一次派单就是一次尝试）。
- **成员会话**：代理、负责的卡、本轮状态（运行中 / 等待 workflow / 空闲 / 需要你）、花费、待投递消息数、未读标记。
- **消息**：类型（状态、派单、完成报告、升级、提问、心跳）、发件会话、收件人（某个会话、某张卡的负责人、一组：全队 / 空闲的成员 / 某个分组）、投递状态（待投递 / 已投递 / 已确认；无法送达附原因）、时间、内容、"来自某个 agent"的标记。
- **决策关卡**：卡片、问题、选项、谁回答（项目负责人或你）、状态。等你回答的关卡进入第 2 批收件箱的"待回答"。

### 2. 成员看板（10.3 的"成员"视图）
- 启用看板的"成员"视图。仿照 Orca 的 agent 看板，按**需要你 / 运行中 / 完成 / 空闲**分列；每个会话一张卡片：代理、负责的卡、状态行、花费、待投递消息数、未读标记。
- 点开会话卡片显示它的**实时输出**（原型里是预设的输出片段，按时间滚动显示），以及当前派单的信息。
- 与依赖图、状态列共用筛选。

### 3. 卡片状态行
- 依赖图、状态列和成员看板的卡片上都显示**状态行**（`FEATURES.md` 1.2）。
- 卡片详情里可以查看状态行的历史，你也可以编辑状态行（例如写目标或约束），修改记入决策记录。

### 4. 通知（10.2）
- 会话从运行中变为完成，或变为需要你时提醒：页面上出现提示，对应的会话和卡片标为**未读**；顶栏有未读计数。
- 点开即清除未读，也可以手动重新标为未读。
- 原型里用一个"模拟下一轮"按钮（放在页面上不显眼但可以找到的位置，标明"演示用"）推进时间：消息投递、心跳、某个派单完成并发出完成报告，从而触发通知。

### 5. 信箱与消息时间线（3.3、10.6）
- **消息时间线**页面：全项目消息按时间排列，可以按成员、卡片、分组、消息类型筛选；显示发件会话、收件人、投递状态；无法送达的高亮并显示原因。
- **按轮投递**：消息先是"待投递"，收件人这一轮结束后才变为"已投递"；"模拟下一轮"推进时更新。
- 成员的消息始终标明"来自某个 agent"。

### 6. 卡片详情的"记录""文件"标签页（10.5）
- **记录**：上下文包（发了什么、没发什么及原因）、与这张卡相关的消息、交接记录、发现、相关决策、派单列表（含完成报告，"状态不明"的派单突出显示）。
- **文件**：本卡相对基线改了哪些文件、diff（沿用已有的 diff 预览）、并行步骤的合回记录。逐行批注在第 4 批做，本批不做。

### 7. 团队页（10.6）
- 成员列表：代理配置、会话、当前卡、预算与花费、表现统计；可以暂停、恢复。

### 8. 暂停与恢复（B11）
- 顶栏的暂停按钮暂停整个项目；卡片菜单、卡片详情、团队页可以暂停某张卡或某个成员。
- 暂停后卡片进入"已暂停"，恢复后回到暂停前的状态；暂停和恢复都写进决策记录。
- 已暂停的项目在顶栏有明显标记；暂停期间"模拟下一轮"不推进被暂停的卡和成员。

### 9. Demo 数据
- **项目 A**（示例）：「成本报价」的成员问「交付产能」的成员人天估算；消息先"待投递"，对方这一轮结束后变为"已投递"，下一轮回复（用"模拟下一轮"可以看到这个过程）。
- **项目 B**（真实记录 + 示例）：「实现」两次派单、「浏览器检查」两次派单，对应真实的两次尝试；至少一个派单"状态不明"（标"示例"）；至少一条无法送达的消息（例如成员想直接发给验证会话，验证会话没有信箱，标"示例"）。
- 每个进行中的卡片都有状态行；状态行的写法参照 `HANDBOOK.md` 10.3。
- 编造的内容一律标"示例"。
