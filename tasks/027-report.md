## 独立验证与申请验收

验收页可以选择模拟身份（项目负责人/成员）、验证代理、方法、是否换模型，以及沿用四态/全通过/首项失败/首项无法验证的预设结果。每次拉起生成新的本地辅助会话，冻结提交、产物修订、规格、测试、交付物和基线版本快照。确定性测试结果是 runtime 在一次性副本内运行的预设模拟，不执行真实测试或模型。显示：新会话、不续接执行方、代理、方法、换模型与否、提交号、无 `.git` 的一次性副本、写入不回收/不合并/结束后删除。

交给验证者的资料列为规格与测试、产物与证据、核心业务逻辑覆盖清单；未交执行日志或执行方对过程的解释。新会话是纯前端示例键，真实外部会话 ID 保持“未记录”。会话按钮复用第 3 批会话面板，可打开结论输出并返回。

申请仅允许项目负责人，成员身份的按钮禁用，同时 runtime 接口也拒绝成员调用。卡片须为进行中；没有结论、并非新会话、复用了执行会话、验证提交或产物修订与当前不符，都拒绝并显示原因。验证完成本身不转换为待验收；成功申请才进入待验收和收件箱。收件箱点击直接打开验收页。

失败、无法验证、未处理项交给下一轮上下文包，列出检查内容、输入、预期、实际状态与证据；不交验证者完整清单。验证历史保留，修改产物后明确提示重新验证，最终验收再次核对提交，防止申请后的产物变化沿用旧结论。

## 验收报告

报告只有通过、失败、无法验证、未处理四态；后三类另有分组列表，无法验证与未处理附原因。其余区块为独立验证结论与会话、执行方标出的核心改动及验证者核对是否标全、对应 diff 入口、项目要求的满足说明、测试/规格前后对比及理由、审查卡结论、被执行方改过的登记文件单列标记。文件页也单独提示登记测试被改。

“核心业务逻辑”覆盖判断、项目负责人是否判为不放宽等内容由负责人/验证者填写，原型以预设演示；不会根据一个测试进程退出码推导业务通过。手动验收只执行硬约束检查，有非通过项仍交给你判断；自动验收按你的条件判断。

## 逐行批注

鼠标路径：打开文件页 → 点击一行，或 Shift+点击另一行选连续范围 → “为选中行写批注” → 输入 Markdown → 保存 → “一次性发回”。批注显示在起始原行下，范围内各行有标记；存原提交、范围与原文，不随模拟成员修改丢失。支持标题、列表、代码块及批注中的粗体/行内代码；HTML 转义。

键盘路径：Tab 聚焦某行 → 方向键/Home/End 移动 → Shift+方向键扩选 → A 打开编辑框 → Ctrl/⌘+Enter 保存 → Tab 到“一次性发回”并 Enter。编辑框 Esc 取消编辑。保存本身不发信；一次发回将所有未解决批注合为一条修改请求，经现有信箱发给负责成员，卡片回到进行中，决定记为“你”。

“模拟成员修改”推进提交并在原片段行上显示示例修正；批注原文与锚点保留。你可逐条核对并标已解决、重新打开；下次发回仅自动带未解决项。请求历史和下一轮上下文保留。

## 自动验收与合并模拟

项目设置默认关闭，五个条件默认勾选，可独立勾选并保存；开启至少保留一项条件。保存决定的决策者为你。

申请时若开启且所选条件全满足，runtime 自动验收，验收决策者为“runtime 自动”；任一所选条件不满足则进入收件箱，报告显示具体缺项。五个条件分别覆盖：独立验证通过、确定性测试全通过、无判断型测试、无核心改动、项目负责人没改过测试。自动验收同样不能绕过新会话与提交核对。

验收通过先记录“已验收”，然后由 runtime 完成产品项目合并或其他项目登记。基线变过时记录在合并结果上重跑确定性测试；预设通过则最终已合并、产出版本 +1；预设失败则退回进行中、版本和冻结的历史保持、旧验证失效，并显示原因。验收与合并/登记结果分别记录，后者决策者为 runtime；看板改动预览也读取实际决策者字段，不把自动决定显示为你。重复验收不会重复增加版本或决定。下游引用旧版本时继续标上游已变；项目记忆继续列出已验收产出历史。
