# 任务 017：项目流程可视化编辑

## 背景

用户审查原型后的意见：编辑项目流程目前是一张表单（选节点、选操作、手动填前置节点 ID），不直观。要求在流程图上直接编辑。用户已确认：**节点位置自动排列**（不支持手动拖动位置）；**去掉原表单**。

**先读：** `prototype/index.html` 中的流程图渲染与布局（任务 011 及返工）、`submitFlow()` / `editFlow()` / `decideFlow()` 等项目流程编辑与变更请求逻辑、原"编辑项目流程"表单；`FEATURES.md` §1.2（执行中修改项目流程按变更请求处理）；`evidence/011/rework-1/report.md`、`evidence/015/report.md`。

## 要做的内容

只改 `prototype/index.html`。三个项目及新建项目都适用。

### 1. 编辑模式

- 项目页流程图右上角加「编辑流程」按钮；进入后显示编辑工具条：「＋ 节点」「提交变更」「放弃改动」，以及改动清单。退出编辑模式前如有未提交改动，提示确认。
- **加节点**：点「＋ 节点」输入名称（自行实现的输入框，不用 `prompt()`），新节点以草稿状态出现在图中，自动布局。
- **加依赖**：从节点右侧（竖向布局时为下方）的连接点拖到目标节点，生成依赖；拖动过程中显示跟随指针的临时连线，可放置的目标节点高亮，不可放置的显示禁止样式。
- **删依赖 / 设条件**：点击连线弹出小菜单：删除；设为条件分支并填写条件文字（或修改、清除条件）。
- **删节点**：选中节点后按 Delete / Backspace 或点菜单"删除"；同时移除其相关连线（在改动清单中列出）。
- **即时校验**（不合法时不允许并给出原因提示）：形成循环、连向自身、重复依赖、跨项目连接；删除或改动已验收 / 执行中节点的依赖时提示影响（例如哪些下游会受影响），由人确认后才加入改动。
- **布局**：始终自动排列；每次改动后重新布局，保留任务 011 的避障、端口间距、自适应宽度 / 图内滚动规则。

### 2. 改动预览与提交

- 改动先不生效：新增的节点与连线用虚线 + 绿色并带"新增"文字标记；删除的用删除线 / 淡化 + 红色并带"删除"文字标记；修改的条件标"修改"。不能只靠颜色。
- 改动清单逐条列出，每条可单独撤销。
- 「提交变更」：项目未开工（无节点开始执行）时直接生效并写入决策记录；已在执行中时生成一条项目流程变更请求进入收件箱（沿用现有变更请求逻辑），批准后生效，驳回则丢弃。提交后退出编辑模式。
- 「放弃改动」一键还原。

### 3. 键盘与窄屏

- 键盘路径（替代拖拽）：图中节点可聚焦；聚焦节点后按 Enter 或菜单键打开节点菜单，包含"添加依赖到…"（弹出同项目节点列表选择目标）、"删除节点"；连线可通过节点菜单中的"管理连线"列出并删除 / 设条件。所有菜单支持方向键、Enter、Esc。
- 窄屏（≤ 760px）：不提供拖拽，使用上述菜单路径；工具条与改动清单不溢出，页面无横向滚动。
- 深色模式正常；新颜色定义为 `:root` 变量并在深色模式块同步。

### 4. 去掉原表单

- 删除原"编辑项目流程"表单及其中的手动 ID 输入；原表单支持的操作（新增节点、修改依赖、删除节点、分支条件）全部由可视化编辑覆盖。

## 不要做的内容（边界）

- 只改 `prototype/index.html`；证据写入 `evidence/017/`；报告写到 `-o` 指定的文件。不改 `FEATURES.md`、`tasks/` 下已有文件、`evidence/001`–`016`。
- 不支持手动拖动节点位置；不改变变更请求的审批规则与其他业务行为；不引入外部库；不做浏览器检查。

`evidence/017/check.mjs`（只用 Node 内置模块，沿用 `evidence/015/check.mjs` 的做法；拖拽通过调用内部的连接函数或派发模拟指针事件测试，报告中说明方式）：

- T01 编辑模式进入 / 退出；有未提交改动时退出需确认
- T02 加节点：新节点以草稿出现在布局中，坐标不与其他节点重叠
- T03 加依赖：合法连接加入改动；循环、自连、重复、跨项目连接被拒绝并给出原因
- T04 删依赖、设 / 改 / 清除条件、删节点（连带删除相关连线）均进入改动清单，并可单独撤销
