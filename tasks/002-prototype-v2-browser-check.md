# 任务 002：原型 v2 浏览器页面检查（只检查，不改代码）

## 背景

任务 001 已在 `prototype/index.html` 中实现原型 v2（见 `tasks/001-prototype-v2.md` 与 `tasks/001-report.md`）。本任务在真实浏览器中检查页面表现，并保存截图作为证据。

先读：`tasks/001-prototype-v2.md`（了解每项功能应有的表现）。

## 要做的内容

1. 启动静态服务：`python3 -m http.server <空闲端口> -d prototype`，端口自选，不要用 8787。
2. 用无头浏览器打开页面。可以使用 Playwright，安装在项目目录以外，例如 `/tmp` 或 npx 缓存；也可以直接使用本机 Chrome 的 headless 模式。视口为 1440×900，浅色模式。
3. 按下列场景依次操作，每个场景截一张整页截图，保存到 `evidence/002/`，文件名按编号命名：
   - S01 收件箱首页：图例中包含强制 / 建议边界的说明；阻塞分组中有 c1b（提问型）和 c1d（达到上限型）
   - S02 打开「技术可行性」(c1a)：信息带中有交付物、资料来源和上限进度条；t2 显示「? 无法判定」以及两个人工判定按钮；签收按钮处于禁用状态并有提示
   - S03 在 c1a 中展开 t2 的证据：可以看到检查方法（method）和修正记录（correction）
   - S04 在 c1a 中展开开发过程卡片：「执行记录」页签中 #1 失败（醒目显示原因），#2 成功；同时截一张切换到「时间线」页签后的图
   - S05 在 c1a 中点「判为通过」，然后签收（`prompt` 对话框直接接受），已签收横幅中出现「保存为模板」
   - S06 点击「保存为模板」并接受默认名：侧栏模板分区出现该模板；打开模板详情页截图
   - S07 打开「竞品与市场规模调研」(c1d)：达到上限横幅，包含部分完成报告和三个按钮，token 进度条为错误色；点「追加预算」后再截一张，状态变为执行中，进度条颜色恢复
   - S08 打开「交付功能：排产看板 v1」(c2)：强制边界带 🔒 和机制说明；补充边界的输入行旁有强制 / 建议下拉框
   - S09 在 c2 中点「worker 启动 prompt」：模态框显示 goal、inputs、rules 三段，其中强制边界标有 [强制]；按 Esc 后模态框关闭（关闭后再截一张）
   - S10 深色模式（`colorScheme: 'dark'`）下的收件箱和 c1a 详情页
   - S11 窄屏 375×812 下的收件箱和 c1a 详情页：没有横向滚动条，三栏变为单列
4. 全程收集浏览器控制台的 error 和 warning，以及未捕获的异常，保存到 `evidence/002/console.txt`。没有的话写"无"。
5. 对每个场景，用 DOM 查询或页面文本断言关键元素确实存在，不要只截图。断言结果保存到 `evidence/002/assertions.txt`，每行格式为 `PASS/FAIL Sxx 描述`。
6. 检查脚本保存为 `evidence/002/browser-check.mjs`（或 `.py`），方便复跑。

## 不要做的内容（边界）

- **禁止修改** `prototype/`、`src/`、`DESIGN.md`、`tasks/` 下除本任务报告以外的任何文件。发现问题只记录，不修复。
- 只允许写入 `evidence/002/` 和本任务的报告文件。浏览器或 Playwright 的安装与缓存放在项目目录以外。
- 不向项目添加任何依赖，不修改 `package.json`。

## 验收标准

- `evidence/002/` 中包含 S01–S11 的截图（S04、S07、S09、S10、S11 各至少 2 张）、`console.txt`、`assertions.txt` 和检查脚本。
- `assertions.txt` 中的结果与截图内容一致。
- 关闭自己启动的 http 服务和浏览器进程，并在报告中说明已清理。
- `git status` 中只出现 `evidence/002/` 和报告文件。

## 报告要求（中文）

- 每个场景的结论（通过 / 不通过）、截图路径，以及看到的问题（布局错位、文字溢出、颜色对比不足等，没有问题也要明确写"无"）
- 控制台错误汇总
- 所用的浏览器及其版本、检查方式
- 清理情况
