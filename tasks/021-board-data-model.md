# 任务 021：原型 v7 第 1 批：数据模型与看板

报告 `tasks/021-report.md` 的第一行写 `session-id: <你的会话 ID>`。

## 背景

Helm 的功能规格已从 v4 改到 v7（`FEATURES.md`）。v4 原型（`prototype/index.html`，约 5900 行的单文件，纯前端模拟，定版于 `5b76bcd`）按"项目 → 流程 → 节点"建模，带一整套规则机制（席位、自主度表、流程变更审批等）。v7 改为：**项目有一块看板，看板上是卡片**；runtime 只守 5 条硬约束，其余由项目负责人决定，规则机制大多取消。

原型分 5 批改到 v7（`FEATURES.md` 第 13 节）。本任务是**第 1 批：换数据模型，做看板**。后续批次会做项目对话与收件箱（第 2 批）、成员与信箱（第 3 批）、卡片详情与验收（第 4 批）、回放与各种库（第 5 批）。

本任务涉及界面，对应的浏览器检查是**任务 022**，022 通过后本任务才算完成。

**先读：**
- `FEATURES.md`：第 0 节（三层与硬约束）、第 1 节（项目与看板，尤其 1.2 卡片、1.3 状态）、9 的 B3、10.3（看板视图）、第 11 节（Demo 数据）、第 13 节（原型分批）
- `prototype/index.html`：`db` 数据（项目 A、项目 B、各节点）、项目页与流程图渲染（`renderProject`、`renderFlowGraph`、`renderFlowSVG`）、可视化编辑（任务 017）、节点详情（`renderNode`）
- `tasks/017-visual-flow-editing.md` 与 `evidence/017/check.mjs`（测试脚本的写法）

## 要做的内容

### 1. 数据模型
用 v7 的模型替换 v4 的"项目 → 流程 → 节点"：

- **项目**：名称、类型、目标、工作现场、项目负责人（代理）、项目指令、项目要求、授权说明（后两项是自然语言文本，第 2 批才有编辑界面，本批先放进数据）、预算与花费、卡片。
- **卡片**（`FEATURES.md` 1.2）：标题、需求、边界、测试（四种类型；每项结果为通过 / 失败 / 无法验证 / 未处理之一）、交付物、资料来源、依赖、**分组标签（可多个）**、父卡、负责的成员、预算与花费、**规格版本**、**产出版本**（含历史）、"上游已变"标记、状态行（数据先放，显示在第 3 批）。规格里每条需求、边界、测试都带**来源**（你 / 项目负责人 / 项目指令 / 卡片模板 / 代理默认 / 出题的会话）。
- **卡片状态**按 `FEATURES.md` 1.3：草稿、待开工、进行中、待验收、已验收、已合并 / 已登记、已暂停、已取消；"重开"是从已验收回到进行中的转换，产出版本在下次验收后 +1。
- **取消的 v4 概念**：席位安排、自主度设置表、流程变更请求的审批、条件分支的选择、单独的"项目流程"层，以及只为这些服务的规则检查（例如 leader 越权被拒、需你批准的流程改动）。界面上对应的入口一并去掉。
- **项目 C 删除**：v7 的 Demo 只有项目 A、B（`FEATURES.md` 第 11 节）。
- 是否把单文件拆成多个文件（例如数据与视图分开），由你决定；拆的话只用普通 `<script src>` 引用本地文件，不引入构建步骤和外部库，并在报告中说明拆分方式。

### 2. 迁移 Demo 数据
- **项目 B「Helm 开发」**（真实记录）：按 `FEATURES.md` 第 11 节项目 B 的表格建卡片，分组为设计、开发、运行时设计、调研、缺陷。卡片内容取自真实记录：v4 里项目 B 的节点、`tasks/001`–`020` 的任务说明与报告、`git log`。真实的会话 ID、任务号、提交号照实填写，并在卡片的资料来源里注明出处。至少包括：
  - 设计：「v2 功能规格」，产出 v1 → v2；它的下游原型卡带"上游已变"标记；
  - 开发：「实现」与「浏览器检查」（「浏览器检查」依赖「实现」；「实现」有两次尝试）；两张都要改 `prototype/index.html` 的原型卡，后一张依赖前一张；
  - 运行时设计：「Codex 沙箱设计」及其子卡「Codex 沙箱补测」（任务 019）；「v6 协作设计」及其子卡「agent team 开源调研」（任务 020）；
  - 调研：单张卡「ADE 底层功能调研」，没有依赖；
  - 缺陷：一条诊断 → 修复 → 回归测试的短链，**整条标"示例"**。
- **项目 A「客户 A · 智能排产承接」**（示例）：把 v4 的 8 个节点迁成卡片，分组"承接评估"；"交付"和"不承接"两条后续卡改为普通卡片（v7 没有条件分支），状态按 v4 的数据合理映射。
- 编造的内容一律标"示例"；不编造真实记录里没有的会话 ID 或提交号。
- 状态要覆盖 1.3 的全部 8 种，方便后续检查；如果真实记录凑不齐，用标"示例"的卡片补足。

### 3. 看板（`FEATURES.md` 10.3）
项目页的主区换成看板，本批做两种视图，第 3、5 批再加"成员"和"回放"（先在视图切换里显示为不可用，并注明在哪一批提供）：

- **依赖图**（默认）：复用 v4 流程图的分层布局、连线避障、图内滚动、焦点小图。卡片为节点，按状态着色；**分组用色块圈出**（一张卡有多个分组时，按第一个分组圈出，其余分组以标签显示）；**父卡可以折叠和展开子卡**；"上游已变"有明显标记，不能只靠颜色。
- **状态列**：按 1.3 的状态分列；已暂停、已取消默认折叠。
- **两种视图共用一组筛选**：分组标签、状态、负责人、"只看我要处理的"（待验收的卡，以及第 2 批收件箱里会出现的事项，本批先按"待验收"实现）。筛选结果在两种视图之间保持。
- **卡片外观**：标题、状态、负责人、分组标签、测试进度（例如 12/14，通过数 / 总数）、规格版本与产出版本（例如"规格 v2 · 产出 v3"）。
- 点卡片打开卡片详情（见第 5 点）。

### 4. 在看板上直接操作（B3）
复用任务 017 的可视化编辑（拖线加依赖、连线菜单、节点菜单、键盘路径、改动预览、即时校验）：

- 支持：新建卡、加 / 删依赖、改分组标签、取消卡。新建的卡是草稿。
- **v7 中你的直接操作立即生效**，不再生成需要审批的变更请求；改动写进决策记录（决策者"你"）。
- 保留即时校验：成环、连向自身、重复依赖、跨项目连接都拒绝并说明原因；涉及进行中或已验收的卡时，提示受影响的下游，确认后才生效。
- 取消一张卡：卡片进入已取消；依赖它的卡显示提示（例如"上游已取消"），由项目负责人后续处理，本批只显示提示。

### 5. 其他页面
- **卡片详情**：从 v4 节点详情改为基于卡片的数据，至少能看到规格（需求、边界、测试，带来源）、依赖（上游、下游、父卡、子卡、产出版本历史）、执行过程（沿用 v4 已有的尝试与步骤展示即可）。完整的标签页重组在第 4 批，本批不必做全。
- **收件箱、代理库、经验库、决策记录、项目记忆、项目设置**等页面：必须能正常打开、没有报错，内容按新模型显示；v7 已取消的内容去掉。本批不做这些页面的改版。
- 侧栏与面包屑：去掉 v4 已取消概念的入口。
- 所有界面文字使用中文。
