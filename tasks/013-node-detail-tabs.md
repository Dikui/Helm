# 任务 013：节点详情页重新归类（页签）

## 背景

用户审查原型后的意见：节点详情页内容排版混乱。当前页面（截图见 `evidence/012/recheck-1/S06-02-navigate-tech.png`）的问题：
- 代理库的"待批准代理提议""教训建议"出现在节点页，且排在需求 / 边界 / 测试之前；
- 需要人处理的事、规格、执行过程、背景信息交错排列；
- "未使用编排""暂无发现""失败 0 项"等空内容各占一张卡片；
- 小图下重复放了整行图例；验收报告把四类结果各列一个标题，大多为"无"。

用户已确认：**使用页签**；**代理提议与教训建议移出节点页**。

**先读：** `prototype/index.html` 中的节点详情渲染函数（`renderNode()` 及其调用的各卡片函数）；`evidence/011/rework-1/report.md`、`evidence/009/report.md`（当前结构）。

## 要做的内容

只改 `prototype/index.html`。所有节点（项目 A、B、C，人工节点，发现生成的节点）都适用。

### 1. 顶部（常驻，不随页签切换）

- 标题、状态、操作按钮（保持现有按钮与禁用规则）。
- **"待你处理"条**：只在有需要人处理的事项时出现，逐条列出，例如：测试无法判定待判定、阻塞等你回答、达到上限、人工关卡待决定、副作用状态不明、合并冲突、退回 / 变更请求待审批、两次确认中的差异待批准、阻塞型发现待处理。每条可点击，切换到对应页签并滚动、聚焦到对应位置。没有事项时整条不显示。

### 2. 四个页签

| 页签 | 内容（按此顺序） |
|---|---|
| **规格与结果**（默认） | 信息带（交付物、资料来源、上限与花费）→ 需求 / 边界 / 测试三栏 → 验收报告：显示通过 / 失败 / 无法验证 / 未处理的计数，**只逐条列出异常项**；没有异常时一行"无异常项" |
| **执行过程** | 执行编排（未使用时只显示一行"本节点由主 agent 直接完成，未使用编排"）→ 尝试记录 → 发现 → 提问与回答 → 执行日志（时间线） |
| **上下文与交接** | 上下游小图（**去掉图例**，图例只保留在项目页）→ 席位安排 → 上下文包 → 交接记录 |
| **变更与记录** | 版本差异、变更请求、退回记录（含发起退回的入口）、本节点相关的决策记录 |

- 原页面底部的"向 leader 提问 / 提出退回"入口：提问放到「执行过程」的提问与回答处，退回放到「变更与记录」。
- 页签标签上显示计数或提醒：如「执行过程 · 2 次尝试」；某页签内有"待你处理"事项时显示小红点并带文字提示（屏幕阅读器可读），不能只靠颜色。
- **空内容合并**：同一页签内没有内容的部分，合并为一行灰字（如"无发现 · 无提问"），不单独占卡片。
- 页签无障碍：`role="tablist"` / `tab` / `tabpanel`，方向键切换，Enter / 空格激活，焦点可见。
- 从收件箱或"待你处理"打开时直接定位到对应页签与位置（例如从「发现」分组打开 → 执行过程页签的发现处）。同一会话中切换节点时默认回到「规格与结果」，除非是定位跳转。
- 窄屏（≤ 760px）：页签栏可在自身内横向滚动，页面本身无横向滚动；深色模式正常。

### 3. 代理提议与教训建议移出节点页

- 节点页不再显示"待批准的代理提议""待批准的教训建议"。
- 它们继续出现在代理库页面和收件箱；收件箱中这类条目点击后打开**代理库**并定位到该条，而不是打开节点。
- 教训建议可以在代理库条目中注明来源节点（链接到该节点），但不在节点页展示。

## 不要做的内容（边界）

- 只改 `prototype/index.html`；证据写入 `evidence/013/`；报告写到 `-o` 指定的文件。不改 `FEATURES.md`、`tasks/` 下已有文件、`evidence/001`–`012`。
- 不改变数据模型与业务行为（验收规则、按钮禁用条件、退回、发现等逻辑保持不变），只改节点页的组织方式与上述跳转。
- 不引入外部库；不做浏览器检查。
