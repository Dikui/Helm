## 逐项原因与修法

### 1. 通知遮挡、没有独立关闭及跨项目混淆

原通知区 `position:fixed`，一直浮在右下角；筛选仅按 unread，未按当前项目限定；只有打开会话才能清除。

改为顶栏里的原生 details 通知区，**默认收起**，摘要显示“通知 N”，展开后在正常文档流中占位，不悬浮覆盖卡片。每次最多显示最近 3 条；提供“关闭通知”和“收起通知”，关闭提示只设置 dismissed，不清除卡片/会话未读。未读计数、读会话/卡片清除和重新标未读沿用原行为。

项目看板、卡片底板、团队、时间线、项目设置/记忆只展示当前项目通知；全局收件箱等全局页面中的通知明确显示项目名。采用手动展开/关闭，不增加自动计时器。

**R01**：默认关闭、展开状态保留、独立关闭不清未读、上限 3 条、收起按钮、A/B 隔离、项目设置隔离、全局通知来源；CSS 检查 position=static。

### 2. 单张卡或成员暂停缺少顶栏标记

原顶栏只检查项目 paused，忽略卡片状态和成员自身的暂停原因。

新增统一暂停汇总，项目看板、团队和时间线共用：显示“已暂停：X 张卡、Y 个成员”，点开查看暂停卡片及单独暂停成员，并可进入卡片/会话。卡数包含预算暂停和叠加范围下仍为已暂停的卡；成员数统计**单独暂停的成员会话**，不把项目或卡片暂停造成的关联冻结重复算成成员手动暂停。明细区写“单独暂停的成员”。整个项目暂停仍额外显示“项目已暂停”。

**R02**：B 单卡暂停 1/0、再暂停另一成员 2/1、顶栏明细与入口、团队/时间线同步、项目暂停叠加与恢复、最后解除后标记消失；A 初始市场调研预算暂停也出现在明细。

### 3. 窄屏原生选择框的固有宽度撑开容器

原 select 只继承通用 max-width，长选项含内部会话键，仍会撑开 label/grid 的固有宽度。页面 overflow-x:hidden 只遮住溢出，没有解决控件尺寸。

会话详情中的 label/select/input/textarea、筛选区的 select/input 显式设置 `min-width:0; width:100%; max-width:100%`，沿用窄屏筛选两列的换行排列。收件会话和时间线成员选项改用代理/卡片可读名与派单编号；value 仍保持原地址/会话键，没有改变发送或筛选语义。

**R03**：375px A/B 详情和时间线控件都渲染，CSS 宽度约束完整，可读选项没有内部 session 键；收件人的 value 仍是原 session 地址。这里验证的是约束及 DOM，scrollWidth 的真实测量留给复检。

### 4. 新卡提交后工具条换行导致图下移

026 的两套真实浏览器回归均显示页面/图内滚动值未变，却整体下移 27.1875px。旧工具条让编辑按钮、说明、动态卡片计数、演示按钮和轮次竞争同一条 flex 换行链；数字宽度变化会跨过换行临界点。

将工具条拆成明确的 grid 行：操作按钮、编辑说明、计数/演示操作。计数使用固定 120px 网格轨道且不换行；窄屏轮次固定占下一行，不再随计数变化挤到新行。保留已有视口/滚动范围恢复、浮层定位和 SVG 布局算法。

**R04**：375/760/1440px，构造与问题对应的 **6/19 → 7/20** 变化；新建、改标签、加/删依赖、取消后，工具条分区、按钮/说明、main/page 已滚位置与参照卡片矩形保持一致；另检查固定轨道和 nowrap。前两批完整滚动/菜单/路径回归也重跑。

没有修改旧浏览器的 <2px 阈值，也没有把原来的 27.1875px 放宽为允许变化；本次未实测浏览器坐标，需 026 复检确认实际位移回到原阈值内。

### 5. 成员卡、团队和会话详情过多重复信息

原标题直接展示内部展示键，状态又复述所在列，配置标签、费用、状态行和告警各自重复标示例；阶段摘要本身也可能带示例前缀。

- 成员标题改为“代理名 · 卡片名”，派单编号单独简短显示；内部会话键保留在会话详情。卡片详情仍有独立入口。
- 成员卡不复述“完成 / 空闲 / 运行中 / 需要你”列名，只保留有额外意义的“等待 workflow”和暂停前状态说明。
- 成员卡只保留一个小“示例”标记，放在状态行首；移除费用、配置和告警的重复示例。状态行数据及历史仍保留来源信息。
- 团队成员标题也采用代理/卡片名，每个成员区块只标一次示例；会话行显示派单编号，内部键和真实 ID 放到详情。
- 会话详情精简标题、状态、输出标题和发信表单。派单/消息各作为独立记录只保留一个小示例标记；预设输出中的重复前缀归一。真实尝试、报告结果、文件出处和消息地址不改。
- 阶段状态行更新先移除重复的演示前缀，避免“示例 · 示例 ·”；用户的目标和约束仍保留。

**R05**：A/B 初始及推进后每个成员卡最多一个示例、标题可读、卡内不重复列名；每个团队成员区块最多一个示例；详情保留内部身份，派单/信件各只标一次；状态更新不生成双前缀。原 025 的状态行完整性、目标保留、消息与会话身份检查同时通过。
