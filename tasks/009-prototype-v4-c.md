## 要做的内容

所有改动只在 `prototype/index.html`。保持单文件、零外部依赖、无构建步骤，界面文字使用中文。

### 1. 产出物预览抽屉（FEATURES §6）

- 右侧抽屉，从节点详情中可以打开：交付物、证据来源、交接记录中的产出路径、批量清单条目的来源行。
- 支持三种内容：
  - **Markdown**：渲染标题、段落、列表、代码块（自行实现最小渲染，不引入库）；
  - **CSV**：渲染为表格；
  - **代码 diff**：带行号，新增 / 删除行用颜色**和** `+` / `-` 符号区分（不能只靠颜色）。
- **高亮被引用的行号**：从带行号的引用（如 `evidence/002/assertions.txt:10`）打开时，滚动到并高亮该行。
- 内容嵌入在页面中（原型是静态页面，不读取外部文件）：
  - 项目 B「浏览器检查」两次尝试的批量清单条目，打开来源时显示**真实**的 `evidence/002/assertions.txt` 和 `evidence/002/recheck-1/assertions.txt` 内容（逐字嵌入，可只嵌入这两个文件），并高亮对应行。
  - 项目 B 的 `--ok` 颜色变更：用 `git log` / `git show` 找到真实的改动，嵌入真实 diff 片段；报告中写明提交号。找不到时改用示例并标注"示例"。
  - 项目 A 至少一个 Markdown 交付物和一个 CSV 资料，内容为模拟数据，标注"示例"。
- 交互：关闭按钮、Esc 关闭、关闭后焦点回到触发元素；窄屏（≤ 760px）下抽屉占满宽度且无横向滚动；深色模式正常。

### 2. 合并顺序与冲突（FEATURES §1.1）

- 产品开发类项目的项目页显示"合并队列"：已验收节点按验收先后排列，每项状态为已合并 / 待合并（需先 rebase 到最新基线）/ 冲突。
- 演示一个冲突：leader 先尝试解决（记录尝试），解决不了时作为一项进入收件箱新增的「合并冲突」分组（FEATURES §6 已更新为 11 组）。人可以选择"已手动解决，继续合并"或"退回节点重新处理"，两种都写入决策记录。
- 演示数据：不得改动项目 B 的真实记录。可以用发现起草出的示例节点与现有节点并行，或新增一个标注"示例"的小型产品开发项目，自行选择最清楚的方式，并在报告中说明理由。所有合并相关数据标注"示例"。
- 文档目录类项目（项目 A）显示"验收后发布"，不显示合并队列。

### 3. 预置一条阻塞型发现

- 在初始数据中加入一条**阻塞型**发现（标注"示例"），出现在收件箱「发现」分组。批准"起草新节点"后，原节点显示暂停并依赖新节点；新节点验收后，原节点恢复（可通过页面上的模拟操作走完）。
