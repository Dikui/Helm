## 1. 从目录切换后说明不可见

**原因：** 当前事件正文、来源说明和事件目录原来共用 `.replay-explanation` 滚动容器。选择目录项只更新正文，原来停在目录底部的滚动偏移仍然保留，导致标题与组织理由不在正文可视区。

**修法：** 将事件目录移出说明容器，放在独立的折叠区与滚动区中。目录展开时限制高度，不挤满说明面板；目录可单独滚动。选择一步后说明容器归顶，组织理由放在正文第一段；目录节点、滑块和图容器均不替换。使用 `focus({preventScroll:true})` 保留所选项的焦点，目录及图的滚动位置不受正文归顶影响。标题仍在固定的控制器头部。

新增独立的 `role="status"`、`aria-live="polite"`、`aria-atomic="true"` 状态区域，随当前步更新步号、标题、新增／拆卡／状态变化及组织理由；选中目录项继续使用 `aria-current="step"`。原生 range 连续拖动仍只更新必要内容。

**测试：** `check.mjs` 的 R07-1 覆盖 1440、1024、375 三种宽度，项目 A、B 的每个目录项；模拟正文停在底部后选择，断言正文归顶、目录滚动不变、焦点与节点身份保留、图滚动保留、标题／理由／变化与状态播报文本同步。

## 2. 375px 打开回放时时间轴不在首屏

**原因：** 窄屏沿用普通项目页的顺序，预算顶栏、项目概况、操作入口和筛选区都在回放之前；侧栏和这些区块叠加，把时间轴推到视口之外。

**修法：** 760px 及以下的回放视图，将视图切换入口和回放面板放到主区开头，项目概况、预算与筛选区放在回放之后，入口和筛选行为保留。进入窄屏回放时同时将 `main` 和 `document.scrollingElement` 归顶。压缩窄屏控制器标题、按钮间距，并增加上下布局中说明面板的空间。普通看板视图及桌面项目区的顺序保留。

**测试：** R07-2 检查两个项目的窄屏 DOM 顺序、回放容器及视图切换入口无重复、实际页面滚动容器归顶、初始目录收起、组织理由置顶；同时回归普通三种看板视图、1024／1440 的原顺序。检查相应 CSS 布局约束。VM 不提供真实浏览器像素排版，因此没有把 DOM 顺序断言当作首屏像素验证。
