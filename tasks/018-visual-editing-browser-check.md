# 任务 018：项目流程可视化编辑浏览器检查（只检查，不改代码）

## 背景

任务 017 在项目页流程图上加入了可视化编辑（拖拽连线、连线菜单、节点菜单、即时校验、改动预览与提交），并删除了原表单（见 `tasks/017-visual-flow-editing.md`、`evidence/017/report.md`）。任务 017 的测试用模拟事件，**真实指针拖拽从未在浏览器中验证过**，这是本次检查的重点。同时回归任务 016 的检查。

## 要做的内容

1. 启动静态服务：`python3 -m http.server <空闲端口> -d prototype`，不要用 8787。无头浏览器（Playwright 装在项目目录以外，或本机 Chrome headless），视口 1440×900，浅色。
2. 场景（截图保存到 `evidence/018/`，文件名以场景编号开头）：
   - S01 项目 C（未开工的部分或新建一个空项目）进入编辑模式：工具条、改动清单可见
   - S02 加节点：用「＋ 节点」及其输入框新建节点，新节点以草稿出现在图中且不与其他节点重叠
   - S03 **真实拖拽加依赖**：用 Playwright 的 `mouse.down / move / up`（分多步移动）从一个节点的连接点拖到另一个节点；截拖动中（临时连线与目标高亮）和放下后各一张；断言改动清单新增一条依赖、图中出现带"新增"标记的虚线连线
   - S04 拖到不合法目标（形成循环、连向自身）：显示禁止样式与原因提示，改动不加入
   - S05 点击连线：弹出菜单，设为条件分支并填写条件文字；再删除另一条连线；截图显示"修改""删除"标记
   - S06 删节点：选中后按 Delete，相关连线一并标为删除
   - S07 改动清单逐条撤销其中一条；「放弃改动」后图恢复原状
   - S08 提交（未开工项目）：直接生效，决策记录中出现；提交（执行中的项目，如项目 A）：生成变更请求进入收件箱，批准后图中生效
   - S09 涉及已验收 / 执行中节点的改动：出现受影响下游提示，确认后才加入
   - S10 键盘路径：Tab 聚焦节点 → 打开节点菜单 → "添加依赖到…"选择目标完成连接；"管理连线"删除一条连线；Esc 关闭菜单
   - S11 原表单不存在（无手动 ID 输入框）
   - S12 窄屏 375×812：编辑模式下使用菜单路径完成一次加依赖；工具条与改动清单不溢出，页面无横向滚动（`document.documentElement.scrollWidth <= innerWidth`）
   - S13 深色模式：编辑模式下有新增 / 删除 / 修改标记的图
3. 每个场景用 DOM / 几何断言，结果保存到 `evidence/018/assertions.txt`，每行 `PASS/FAIL Sxx 描述`。S12、S13 用 `getComputedStyle` 抽查工具条、标记文字、菜单的对比度 ≥ 4.5:1，连线与连接点 ≥ 3:1。编辑后重新布局，断言节点不重叠、节点不超出图容器可见 / 可滚动区域。
4. **回归**：复制 `evidence/016/browser-check.mjs` 到 `evidence/018/regression-016/` 下运行（不改原脚本和原证据）；对每条失败判断是预期变更还是回归问题，预期变更时用新方式补测并记录。
5. 控制台 error、warning、未捕获异常保存到 `evidence/018/console.txt`，没有写"无"。检查脚本保存为 `evidence/018/browser-check.mjs`。
