# 任务 014：节点详情页签浏览器检查（只检查，不改代码）

## 背景

任务 013 把节点详情改为常驻顶部 +「待你处理」条 + 四个页签，并把代理提议、教训建议移到代理库（见 `tasks/013-node-detail-tabs.md`、`evidence/013/report.md`）。本任务在真实浏览器中检查，并回归任务 012 复检的检查。

## 要做的内容

1. 启动静态服务：`python3 -m http.server <空闲端口> -d prototype`，不要用 8787。无头浏览器（Playwright 装在项目目录以外，或本机 Chrome headless），视口 1440×900，浅色。
2. 场景（截图保存到 `evidence/014/`，文件名以场景编号开头）：
   - S01 项目 A「技术可行性」：顶部有「待你处理」条（无法判定待判定）；4 个页签，默认「规格与结果」；截四个页签各一张
   - S02 点击「待你处理」中的无法判定条目：切到正确页签并定位到该测试（截图显示该测试在可视区域内）
   - S03 「交付产能」（提问阻塞）、「市场调研」（达到上限）、「成本报价」（人工关卡）：各自的待处理条目与定位
   - S04 项目 B「实现」（副作用状态不明）、项目 C 合并冲突节点、阻塞型发现所在节点：待处理条目与定位
   - S05 没有待处理事项的节点（如已验收的「需求澄清」）：不显示「待你处理」条
   - S06 空内容合并：一个无发现、无提问的节点，执行过程页签中显示合并的一行灰字而不是空卡片
   - S07 验收报告：「技术可行性」与项目 B「浏览器检查」的验收报告显示四态计数、只列异常项；无异常时显示"无异常项"
   - S08 「上下文与交接」页签的小图没有图例；项目页仍有图例
   - S09 节点页不出现代理提议与教训建议；代理库页面有；从收件箱点击代理提议条目打开代理库并定位到该条
   - S10 从收件箱的发现、无法判定、人工关卡、副作用不明、合并冲突、退回请求各打开一次，落在正确页签与位置
   - S11 键盘：Tab 到页签栏，方向键切换，Enter / 空格激活，焦点可见（截图）
   - S12 深色模式：「技术可行性」四个页签中任选两个 + 待你处理条
   - S13 窄屏 375×812：「技术可行性」页签栏在自身内横向滚动，页面无横向滚动（`document.documentElement.scrollWidth <= innerWidth`），内容没有逐字换行
3. 每个场景用 DOM 断言（页签 `aria-selected`、元素是否在可视区域 `getBoundingClientRect`、元素是否存在于对应 tabpanel 内等），结果保存到 `evidence/014/assertions.txt`，每行 `PASS/FAIL Sxx 描述`。S12、S13 用 `getComputedStyle` 抽查页签（选中 / 未选中 / 焦点）、红点文字、「待你处理」条对比度 ≥ 4.5:1。
4. **回归**：复制 `evidence/012/recheck-1/` 中的检查脚本到 `evidence/014/regression-012/` 下运行（不改原脚本和原证据）；对每条失败判断是预期变更（节点页结构变化）还是回归问题。
5. 控制台 error、warning、未捕获异常保存到 `evidence/014/console.txt`，没有写"无"。检查脚本保存为 `evidence/014/browser-check.mjs`。
