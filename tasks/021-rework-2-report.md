## 1. 松开后滚动跳动

**原因**：原渲染替换整个主区 HTML，也替换图内 SVG。合法连接让两张卡从纵排改为横排，复检中的图高从 310 降至 173px；新增记录不足以抵消缩短，主区 scrollHeight 从 1072 降至 998px，900px 高主区的最大 scrollTop 从 172 降至 98。浏览器因此钳制了原滚动位置，画布和起点相对视口下移 74px。即使赋回 172，如果没有足够的滚动范围，仍只能得到 98。

**修法**：

- `render()` 与 `refreshFlowLayout()` 保存主区、页面及图容器的上下/左右滚动值。图按项目和焦点卡匹配，状态列容器也保存横向位置。
- 渲染完成后，先检查新的滚动范围是否能容纳原位置。必要时在主区、画布或页面尾部加最小的无内容、不可交互、`aria-hidden` 的尾部。尾部是 HTML，不修改 SVG 尺寸、卡片坐标、版本或依赖路径。
- 原主区位置 172 需要至少 1072px 的内容高；新内容只有 998px 时，保留 74px 尾部即可。窄屏图内纵向、长图横向缩短和页面滚动采用相同原则。
- 先保留范围，再恢复位置；恢复卡片焦点使用 `focus({preventScroll:true})`，不调用 `scrollIntoView`。正常打开菜单/表单的交互聚焦保留，数据提交后的恢复不会主动滚去新卡或通知。
- 主区、图容器及页面关闭浏览器自动滚动锚定，避免原生锚点选择叠加位置变化。每次完整重渲染按当前位置重新计算所需范围，显式页面导航清除临时尾部。

初始页面、无须保留范围时不增加尾部；卡片仍按新依赖正常重排。保留少量尾部空白是为了让原滚动位置仍能到达，避免缩短内容时浏览器强制拉回。导航和后续渲染会清理或重新计算，不写入卡片数据。

**测试**：S01 覆盖加依赖、新建卡、改标签、删依赖、取消卡；S02 通过指针结束路径复现 1072→998，并带负对照；S03 覆盖图内纵向、横向及页面缩短；S04 覆盖恢复焦点、刷新图与导航清理。

## 2. 空白说明框

**原因**：SVG 中的 `hidden` 属性没有提供和 HTML 相同的默认隐藏效果。仅在 g 上设置属性，子 rect 仍以 inline/visible 绘制，所以空闲和结束后留下空白框。

**修法**：增加显式、限定在 SVG 内的规则：

```css
.flow-svg [hidden], .flow-svg [hidden] * {
  display: none !important;
}
```

父组及其所有子元素都不绘制，临时线和说明文字同样遵循。拖动时移除 hidden 后正常出现；合法完成、自身/成环/重复拒绝、取消及 Esc 后恢复 hidden，空框、文字与临时线完全消失。不改变图的几何或已预留标签空间。

**测试**：S05 的样式计算桩特意采用“SVG hidden 默认不隐藏”的模型，要求作者规则存在；验证空闲、拖动中和六类结束路径中的父组、rect、临时线可见性，避免只查属性就认为浏览器已经隐藏。

## 3. 拖动反馈覆盖通知

**原因**：已有“已生效”通知和拖动反馈都固定在右下角，z-index 只决定谁覆盖谁，不能避免文字互相遮挡。

**修法**：共享右下角位置，但互斥显示。开始拖动时收起当前通知，保留它原来是否隐藏的状态；拖动期间只显示反馈。结束、拒绝、取消后先隐藏拖动反馈，再恢复原通知或由直接操作的结果通知替换。原本已隐藏的通知不被重新打开。切换不重渲染，不引入新的文档流占位。

**测试**：S06 覆盖合法结束、自身拒绝、取消三类路径及原本隐藏的通知。每个阶段至多一个浮层可见，不以提高 z-index 代替互斥。原成功、中性、错误样式及对比度保持。
