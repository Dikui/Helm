# 任务 012：项目流程图浏览器检查（只检查，不改代码）

## 背景

任务 011 把项目页的项目流程改成了 SVG 有向图（见 `tasks/011-prototype-flow-graph.md`、`evidence/011/report.md`）。本任务在真实浏览器中检查图的实际显示效果，并回归任务 010 的检查。

## 要做的内容

1. 启动静态服务：`python3 -m http.server <空闲端口> -d prototype`，不要用 8787。无头浏览器（Playwright 装在项目目录以外，或本机 Chrome headless），视口 1440×900，浅色。
2. 场景（截图保存到 `evidence/012/`，文件名以场景编号开头）：
   - S01 项目 A 项目页：图中 8 个节点、所有依赖连线带箭头；4 个并行节点同层；两条条件分支连线旁有"若可行 / 若不可行"；图例存在
   - S02 项目 B 项目页：顺序 4 个节点；"浏览器检查 → 实现"的退回用不同线型标出
   - S03 项目 C 项目页：并行与合并关系清楚；发现生成的节点（如已有）带发现标记
   - S04 悬停一个节点（如项目 A「汇总结论」）：上下游连线高亮、其他连线变淡（截图）
   - S05 键盘：Tab 聚焦到图中节点，Enter 打开节点详情
   - S06 节点详情小图：「汇总结论」详情中的小图只含它和直接上游、直接下游，点击小图中的节点可跳转
   - S07 在项目 C 处理阻塞型发现、批准起草新节点后，项目 C 图中出现新节点及其依赖
   - S08 深色模式：项目 A、项目 C 项目页
   - S09 窄屏 375×812：项目 A、项目 C 项目页为竖向布局，无横向滚动（`document.documentElement.scrollWidth <= innerWidth`），节点文字没有被挤成逐字换行
3. 每个场景用 DOM / 几何断言（例如用 `getBoundingClientRect` 检查节点之间不重叠、连线的 SVG 路径端点落在节点边上、标签不被裁切），结果保存到 `evidence/012/assertions.txt`，每行 `PASS/FAIL Sxx 描述`。S08、S09 用 `getComputedStyle` 抽查节点文字、状态标签、条件文字对比度 ≥ 4.5:1，连线与背景 ≥ 3:1。
4. **回归任务 010**：复制 `evidence/010/browser-check.mjs` 到 `evidence/012/regression-010/` 下运行（不改原脚本和原证据）；对每条失败判断是预期变更（例如依赖文字行被移除）还是回归问题。
5. 控制台 error、warning、未捕获异常保存到 `evidence/012/console.txt`，没有写"无"。检查脚本保存为 `evidence/012/browser-check.mjs`。

## 不要做的内容（边界）

- 只写入 `evidence/012/` 和本任务报告文件；浏览器与 Playwright 安装缓存放在项目目录以外；不加依赖；只访问本地静态服务。
