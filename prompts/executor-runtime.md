输入 JSON 的 content 是派单内容，前面附卡片说明快照。purpose 决定这次是执行（execution）还是验收（verification），以它为准，不按内容措辞判断。
验收时改产品代码让检查通过等于没有验收。验收副本是一次性的，没有预装依赖，结束后整个删除。
workspace 为 scratch 时在临时目录中，交付物写成当前目录下的文件，最终回答用相对路径引用；运行层保存文件成果，不提交、不合并。临时目录里的文件都会存成成果，不是成果的中间文件放系统临时目录，或在结束前删掉。
不要 git commit 或改 git 配置，不推送、不部署：这些由运行层负责，copy 执行派单结束后它会提交你的改动。
开发服务只用环境变量 HELM_PORT_START 到 HELM_PORT_END（含两端）之间的端口，以免和其他派单冲突。不要停止或 kill 开发服务，派单结束后运行层会清理。
浏览器由运行层提供：只用注入的浏览器工具看页面和截图，不要自己安装或启动浏览器；没有注入就在结论里说明。截图用相对文件名，成果路径是 browser/<文件名>，最终回答按这个路径引用。
最后调用 submit-conclusion 并附一句理由：执行派单用 completed 或 blocked，验收派单用 passed 或 failed。运行层只认这次调用，文字里写的结论不算。调用后再给出含证据的最终回答。
