# 05 — 执行者提示词补齐运行层约定

**What to build:** 执行者的默认提示词写清 Helm 运行层的三条约定，让执行者不再因为不了解运行层而做错：开发服务不用自己停，派单结束时由运行层清理副本里的进程；结束前必须调用"提交结论"，只在文字里写结论算未声明；截图用相对文件名，最终回答写成果列表里的实际路径。来源：第一版 2048 端到端中，验收者试图 kill 服务被沙箱拦下而判失败、一次执行派单漏调"提交结论"、截图写到被拒绝的位置或给出错误路径（见 [任务单 15](../../helm-v1-p1/issues/15-default-prompts-and-2048.md) Comments）。

调度者侧的问题（汇总报告不可靠、派验收单时放宽标准）属于在 Helm 外另做的调度者技能，不在本单范围。把提示词、skill、工具做成按模板的配置属于第二阶段（见 [spec](../../helm-v1-p1/spec.md) Out of Scope），本单不做。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 执行者提示词：结束前必须调用"提交结论"，只在文字里写结论记为未声明、不算完成
- [x] 执行者提示词：截图用相对文件名，最终回答写成果列表里的实际路径

## Comments

在 `src/prompts.ts` 的执行者提示词中补齐进程清理、必须提交结论和截图路径三条运行层约定，并在真实 Claude 执行者驱动的新开、续跑 SDK 查询边界断言注入内容；`npm run check` 和全量 `npm test`（202 个测试）通过，浏览器相关测试使用替身。
- 2026-10-22 调度者：沙箱外真实冒烟（browser 1/1、executor 5/5、coordinator 6/6）显示执行者都调用了提交结论、没有自行 kill，截图用相对文件名，但最终回答写的是 round-N.png 而成果路径是 browser/round-N.png——执行者在派单中看不到成果列表。提示词改为直接说明成果路径是 browser/<文件名>。修复单 04 同轮验证：10 个真实会话无 METHOD_NOT_ALLOWED 拒绝事件。
- 2026-10-23 调度者：干净环境冒烟中 8 个真实执行者都调用了提交结论，截图路径与成果 `browser/<文件名>` 一致，无执行者自行 kill/pkill，截图路径提示词已验证。
