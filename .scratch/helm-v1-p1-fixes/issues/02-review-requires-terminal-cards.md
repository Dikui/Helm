# 02 — 发起审核前卡片须全部进入终态

**What to build:** 调度者发起审核时，只要还有卡片没到"完成"或"取消"，运行层就拒绝，并在结构化错误里列出这些卡片，以及当前允许的操作（如标记完成、取消卡片），调度者据此补齐后再发起审核。来源：第一版 2048 端到端中，最后一张整体验收卡片验收已通过但没有标完成，审核仍被发起并被接受，工作结束时卡片还停在"验收中"（见 [任务单 15](../../helm-v1-p1/issues/15-default-prompts-and-2048.md) Comments）。

**Blocked by:** 01 — 审核附件识别整体验收

**Status:** resolved

- [x] 存在非终态卡片时，发起审核被拒绝，错误码和原因明确，错误里列出这些卡片，记"操作被拒绝"事件
- [x] 所有卡片都是完成或取消时，可以正常发起审核
- [x] 用同一个 key 重复调用、且审核关卡已存在时，仍返回原关卡（幂等不受影响）
- [x] 审核退回后再次发起审核时同样检查

## Comments

发起新审核前检查所有卡片终态，以 NON_TERMINAL_CARDS 结构化错误和拒绝事件列出卡片及允许操作，保留原 key 幂等返回；假驱动回归覆盖五种非终态、验收通过未标完成、完成或取消后重试及审核退回重提。
