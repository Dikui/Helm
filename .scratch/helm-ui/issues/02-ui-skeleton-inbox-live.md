# 02 — 界面骨架：托管、收件箱与实时更新

**What to build:** 用户运行 `helm serve` 后在浏览器打开同一地址，看到主界面的工作收件箱：按"等你处理 / 进行中 / 已结束"分组，每行有标题、一句"正在做什么"、状态计时、卡片完成数和 token 合计；被运行层暂停的工作标出原因；能按标题搜索；侧栏底部显示执行者并发数、上限和排队数。状态变化经 SSE 推送后页面自动更新，断线重连补齐；操作被拒时显示运行层给出的原因。侧栏可切换中 / EN，跟随系统深浅主题。本单建立前端工程和"jsdom 渲染整个应用 + 假驱动的真实 `helmd`"测试边界，后续任务单都在其上追加。见 [需求文档](../spec.md)"托管与工程""数据读取与实时""运行层补的读取"，界面以 [设计稿](../../../design/INDEX.md) 的 `main.html` 为准。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] `npm run build` 同时产出 `helmd` 和前端静态产物；`helmd` 对 GET 返回静态文件，未知路径回落 `index.html`，路径穿越被拒；`/api/*`、`/mcp`、`/events` 的 POST 行为不变
- [ ] `list-works`、`get-work` 返回 `title`（第一条用户消息首行，过长截断）；`list-works` 另返回一句话摘要、当前状态起始时间、卡片完成数 / 总数、未决关卡摘要
- [ ] 收件箱分组规则：有未决关卡、审核中或被运行层暂停 → 等你处理；其余未结束 → 进行中；完成、取消 → 已结束。琥珀色只给等你处理
- [ ] 浏览器端用 `fetch` 读取 POST `/events` 流，收到事件后重新读取受影响的数据；断线后带 `Last-Event-ID` 重连，不漏事件
- [ ] 计时每秒走，起点取自数据时间戳；中英切换只翻译界面文字，选择存在浏览器本地
- [ ] 设计变量迁入前端工程，不在运行时引用 `design/`；不引入 UI 组件库
- [ ] HTTP 接口测试覆盖新增字段和静态托管；jsdom 整页测试覆盖分组、SSE 推送后更新、重连补齐、操作被拒显示原因、搜索
- [ ] `npm run check`、`npm test` 通过；沙箱外 `npm run test:real` 通过
