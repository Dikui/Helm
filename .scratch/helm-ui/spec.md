# Helm v1 第三阶段：界面

Status: ready-for-agent
Map: [Helm v1 设计](../helm-v1/map.md)

本文覆盖 [15](../helm-v1/issues/15-v1-slice.md) 定的第三阶段界面部分。ACP 驱动已在[第三阶段驱动 spec](../helm-v1-p3/spec.md) 完成；界面做完后重跑 2048 不在本文。界面必须项来自 [12](../helm-v1/issues/12-monitoring-ui.md)，技术栈来自 [04](../helm-v1/issues/04-tech-stack.md)（React + Vite 静态页面，由 `helmd` 托管，实时用 SSE，操作用 HTTP POST），对外接口与不认证的取舍来自 [13](../helm-v1/issues/13-olympus-interface.md)。布局、交互和文案以 2026-10-24 定稿的设计稿为准：[design/INDEX.md](../../design/INDEX.md) 登记的 `main.html`、`new-work.html`、`settings.html`，各页开头的交接说明列出了数据、状态、交互和"开发时补"的部分。术语以 [GLOSSARY.md](../../GLOSSARY.md) 为准。已有任务单 [01 界面保存 Agent 模板](issues/01-save-agent-template.md) 是本文的一部分，拆单时保留它的编号和内容。

## Problem Statement

用户现在只能用 `helm` 命令行和 Helm 打交道：发消息、看对话、决定关卡都要敲子命令，看不到卡片图，也看不出哪项工作在等自己。几项工作同时进行时，用户要逐个查询才知道谁卡在关卡上、哪张卡片被打回、调度者这一轮在做什么。派单输出、调度轮次、事件时间线都只能翻 JSON。改 Agent 模板只能去改文件。[15](../helm-v1/issues/15-v1-slice.md) 把"v1 是否做完"押在界面上，成功标准"在一个界面里看到每张卡片的状态、谁在做、做到哪一步"目前做不到。

## Solution

`helmd` 在同一个本机端口上托管一个网页界面，用户打开浏览器就能用 Helm 的全部用户操作。界面分三页，和设计稿一致：

- **主界面**：左栏是工作收件箱，按"等你处理 / 进行中 / 已结束"分组，每行一句"正在做什么"、计时和计数，展开即可直接决定关卡或审核。右侧是选中工作的工作页：对齐中时是对话加工作说明草稿和确认关卡；执行中可在"对话 / 调度结构 / 工作说明"三个视图间切换。对话视图里能看到调度者本轮的步骤，轮次运行中发的消息排进"下一轮处理"，⌘⏎ 打断本轮。调度结构视图有卡片图、泳道时间线、调度者和事件四个标签，加右侧的卡片检查器。
- **新建工作**：选项目、写第一句需求、选调度者模板，发送后进入主界面的对齐中。还没登记项目时引导登记。
- **设置**：Agent 模板（按角色分组，列表直接显示可用性和原因，详情可编辑保存或复制为新模板）、项目、运行参数。

所有状态经 SSE 实时推送，不用手动刷新。界面只调用现有操作表生成的 HTTP 接口；缺的读取字段补在现有读操作上，只新增设计稿必需的两个读操作。

## User Stories

1. As a 用户, I want 运行 `helm serve` 后在浏览器打开它的地址就看到界面, so that 不用另装或另起前端服务。
2. As a 用户, I want 收件箱把等我处理的工作排在最上面并用琥珀色标出, so that 一眼知道该先处理哪项。
3. As a 用户, I want 收件箱每行显示工作标题、一句"正在做什么"、状态计时、卡片完成数和 token 合计, so that 不点进去也知道每项工作的进展。
4. As a 用户, I want 被运行层暂停的工作在收件箱标出原因（调度者额度用完、连续失败 3 次）, so that 工作不会悄悄停下。
5. As a 用户, I want 在收件箱里展开一行就看到最近几步，并直接决定关卡或接受 / 退回审核, so that 简单的决定不用打开工作页。
6. As a 用户, I want 按标题搜索工作, so that 工作多了也能很快找到。
7. As a 用户, I want 侧栏底部看到执行者并发数、上限和排队数, so that 知道为什么有的派单还没开始。
8. As a 用户, I want 在新建页选项目、写一句需求、选调度者模板就能新建工作, so that 其余细节交给调度者在对齐里问。
9. As a 用户, I want 新建前看到项目的基准分支、基准提交和未提交改动提醒, so that 知道未提交的改动不会进入工作分支。
10. As a 用户, I want 还没登记项目时页面引导我填路径登记, so that 第一次使用不会卡住。
11. As a 用户, I want 发送第一条消息时网络重试不会建出两项工作, so that 不用清理重复的工作。
12. As a 用户, I want 对齐中时左边是我和调度者的对话、右边是工作说明草稿逐版显示并高亮新增条目, so that 我能看清每一版改了什么。
13. As a 用户, I want 在对话的关卡里或工作说明旁边点"确认这一版", so that 确认后工作才开分支、开始执行。
14. As a 用户, I want 对话里消息和关卡按时间穿插，关卡可以选选项或自由回答, so that 和调度者的往来在一个地方。
15. As a 用户, I want 发消息时注明是针对整项工作、某张卡片还是某个关卡, so that 调度者知道我指的是什么。
16. As a 用户, I want 看到调度者本轮正在做的步骤和用时, so that 知道它在想什么、卡在哪里。
17. As a 用户, I want 轮次运行中发的消息显示在"下一轮处理"里，并能用 ⌘⏎ 立即打断本轮, so that 急事不用等这一轮结束。
18. As a 用户, I want 卡片图自上而下分层显示，同层可并行、连线表示依赖并汇合，关卡是节点，取消的卡片用虚线保留，打回次数标 ↺, so that 一眼看懂并行、串行和回溯。
19. As a 用户, I want 每张卡片显示状态、执行者模板、当前步骤号和最新一步的一行摘要并实时更新, so that 知道谁在做、做到哪一步。
20. As a 用户, I want 一条泳道时间线显示每张卡片的执行和验收派单，重叠表示并行，"验收 ✗ → ↺ 执行"表示打回, so that 看清时间都花在哪里。
21. As a 用户, I want 点一张卡片在检查器里看它的派单历史、每次派单的结束方式、自报结论及理由、最终回答, so that 知道为什么被打回。
22. As a 用户, I want 按步骤查看派单输出，并看到卡片成果（分支、文件、测试输出）, so that 能核对执行者实际做了什么。
23. As a 用户, I want 看到调度者当前状态（运行中 / 空闲 / 连败暂停）、每个调度轮次及其输出、调度笔记各版本, so that 能追溯调度者的决策。
24. As a 用户, I want 一条可按卡片、派单、执行方筛选的事件时间线，点事件跳到对应派单输出的那一步, so that 出问题时能顺着时间往回查。
25. As a 用户, I want 执行中随时切到"工作说明"视图看生效版本和历史版本, so that 不用翻对话找当初定了什么。
26. As a 用户, I want 审核时看到汇总报告、工作分支相对基准 ref 的 diff、整体验收结论、被拒绝的操作数和未声明结论的派单数，只能接受或退回并附意见, so that 审核有据可依。
27. As a 用户, I want 在工作页的"操作"菜单里暂停 / 恢复 / 取消工作、换调度者模板, so that 不用命令行。
28. As a 用户, I want 在卡片检查器里暂停 / 恢复 / 取消卡片, so that 能单独止住一张跑偏的卡片。
29. As a 用户, I want 取消、删除输出这类不可逆操作先让我确认, so that 不会误点。
30. As a 用户, I want 输出总量超过阈值时界面提示，已结束的工作可以导出和删除输出，删除前提示先导出，删除后显示"已删除", so that 磁盘不会被悄悄占满。
31. As a 用户, I want 显示卡片副本路径的地方提示别在副本目录开终端, so that 我不会和执行者抢着改同一个目录。
32. As a 用户, I want 设置页按角色分组列出 Agent 模板，直接显示是否可用及原因和正在使用的派单数、工作数, so that 换模板前知道影响。
33. As a 用户, I want 在设置页编辑模板的驱动、模型、推理强度、fast、计费方式、职责说明和 `prompt.md` 并保存, so that 不用去改文件。
34. As a 用户, I want 把所选模板复制为新模板, so that 能在现有配置上做变体。
35. As a 用户, I want 文件在我编辑期间被编辑器改过时保存提示冲突而不是覆盖, so that 不会丢掉别处的修改。
36. As a 用户, I want 在设置页登记项目、设项目的默认调度者模板, so that 新建工作时不用每次选。
37. As a 用户, I want 在设置页改执行者并发上限、派单看门狗、轮次看门狗和输出提示阈值, so that 按机器和额度调整。
38. As a 用户, I want 在侧栏切换中文和英文界面, so that 用自己习惯的语言看界面文字。
39. As a 用户, I want 界面在深色和浅色系统主题下都可读, so that 跟随系统设置。
40. As a 用户, I want 页面断网重连后自动补上错过的事件, so that 不用手动刷新也不会漏状态。
41. As a 用户, I want 操作被拒绝时看到运行层给出的原因, so that 知道下一步该怎么做。

## Implementation Decisions

### 托管与工程

- 前端是仓库内一个独立的 Vite + React + TypeScript 工程，和 `src/` 分开，有自己的 tsconfig；`npm run build` 先编译 `helmd` 再构建前端，产物进 `dist/` 下的静态目录。开发时可用 Vite dev server 代理到本机 `helmd`。
- `helmd` 对 GET 请求托管静态产物：存在的文件按扩展名返回，其余路径返回 `index.html`（前端自己路由）。只读静态目录内的文件，拒绝路径穿越。`/api/<操作>`、`/mcp`、`/events` 的现有行为不变，仍只接受 POST。
- 界面和接口同源（同一个 `127.0.0.1` 端口），不加 CORS，不加认证，沿用 [13](../helm-v1/issues/13-olympus-interface.md) 已接受的风险。
- 前端路由三页：主界面（可带选中的工作 id）、新建工作、设置（可带分区和模板 id）。URL 可直接打开、刷新不丢位置。
- 界面样式沿用设计稿的设计变量（`design/kit/tokens.css` 的 zinc 中性色、状态色、深色主题）和组件样式，迁入前端工程后由前端维护；设计稿不作为运行时依赖。不引入 UI 组件库。
- 卡片图的分层布局用现成的有向图布局库（如 dagre 或 elkjs）计算坐标，界面只负责绘制，支持平移缩放。
- 中英文切换用轻量的 i18n 字典，只翻译界面自身文字；消息、步骤、工作说明等 agent 产出原样显示。所选语言存在浏览器本地。

### 数据读取与实时

- 界面只通过操作表生成的 HTTP 接口读写，一个薄的请求函数统一处理错误体（`code`、`reason`、`allowedOperations`），把 `reason` 显示给用户。
- 实时：浏览器用 `fetch` 读取 POST `/events` 的流（`EventSource` 只支持 GET，`/events` 保持 POST 不改），断线后带 `Last-Event-ID` 重连补齐。收到事件后按事件涉及的工作、卡片、派单重新读取对应数据，不在前端用事件自行推导状态。
- 计时每秒在前端走，起点取自数据里的时间戳。
- 带 `key` 的操作（发消息等）由前端生成 key，重试沿用同一个 key，保证不重复创建。

### 运行层补的读取

只补设计稿和必须项需要、现有读操作给不出的字段：

- **工作标题**：任务库不存工作标题。标题取这项工作第一条用户消息的首行，过长截断；不新增字段，也不让调度者起名。`list-works` 和 `get-work` 返回 `title`。
- **`list-works` 每项工作补**：标题、一句话摘要（最新一条事件的用户可读摘要）、当前状态的起始时间（用于计时）、卡片完成数和总数、未决关卡的摘要。token 合计已有。
- **`list-projects` 每个项目补**：当前分支名、HEAD 提交、未提交改动数，供新建页显示基准和提醒。读不到 git 状态时返回原因，不报错。
- **`list-agent-templates` 每个模板补**：`revision`（见任务单 01）和使用情况（正在运行的派单数、以它为调度者模板的未结束工作数）。
- **`send-message` 补可选 `cardId`**，与已有的 `gateId` 一样记录在消息上，调度者在对话里能看到。
- **新增 `list-rounds`**（调用方 `user`、`coordinator-round`）：一项工作的全部调度轮次，含轮次号、模板、状态、起止时间、token、结束原因，以及当前排队待下一轮处理的用户消息。调度者当前状态（运行中 / 空闲 / 连败暂停）由此和工作状态得出。
- **新增 `get-round-output`**（调用方 `user`）：按步骤读取一个调度轮次的输出，分页方式与 `get-dispatch-output` 一致。
- 新操作和新字段照常进 MCP 工具和 `helm` 命令行，不为界面另开接口。

### 主界面

- 收件箱分组规则：有未决关卡、在审核中或被运行层暂停的工作归"等你处理"；其余未结束的归"进行中"；已完成和已取消的归"已结束"。琥珀色只给"等你处理"；进行中用蓝色转圈。
- 收件箱行内能直接做的只有决定关卡和审核接受 / 退回；审核的 diff 等详情仍在工作页查看。
- 对话视图的发消息框带一个范围选择（整项工作 / 某张卡片 / 某个未决关卡），分别对应 `send-message` 不带、带 `cardId`、带 `gateId`。
- "本轮步骤"取自运行中轮次的输出；"下一轮处理"取自 `list-rounds` 的排队消息。⌘⏎ 调用 `interrupt-round`。
- 调度结构视图四个标签：图、时间线、调度者、事件。点图上的节点切换右侧检查器；悬停高亮上下游。时间线的泳道和色块由派单的起止时间和用途得出，竖线表示现在。
- 检查器显示选中卡片的派单历史（含打回回路和不通过的理由）、派单输出（按步骤）、成果，以及暂停 / 恢复 / 取消卡片。
- 工作说明视图显示生效版本，可切换查看历史版本；要改只能在对话里让调度者起草新版。
- 对齐中（工作处于对齐阶段）时工作页只有对话和右侧工作说明草稿，草稿逐版显示并高亮相对上一版新增的条目；确认关卡在对话和草稿旁各有一个入口，调用同一个 `decide-gate`。
- "操作"菜单：暂停 / 恢复 / 取消工作、换调度者模板、导出输出、删除输出（仅已结束的工作）。取消工作、取消卡片、删除输出需二次确认；删除输出未导出时先提示导出（沿用 `delete-outputs` 的 `confirm`）。
- 输出总量超过阈值时，界面顶部显示提示，指向设置里的阈值和已结束工作的导出 / 删除。

### 新建工作

- 只填项目、第一句需求、调度者模板（默认取项目的默认调度者模板，不可用的模板显示原因且不可选）。发送调用 `send-message`（带 `projectId`），成功后跳到主界面这项工作的对齐中。
- 登记项目用弹窗，调用 `register-project`；没有任何项目时页面直接显示登记表单。

### 设置

- Agent 模板：列表按角色分组；详情表单的字段与 `templates` 的 schema 一致；保存和复制为新模板调用任务单 01 的 `save-agent-template`。编辑已有模板时角色不可改；保存冲突时提示用户重新载入，不覆盖。新建 API 模板时提示用户去配置主目录。不提供删除模板。`skills/` 只显示目录内容，不在界面编辑。
- 项目：列表显示名称、路径、默认调度者模板、工作数；可登记项目、改默认调度者模板。
- 运行：并发上限、派单看门狗（墙钟 / 无输出）、轮次看门狗（总时长 / 无输出）、输出提示阈值，各调用对应的 `set-*` 操作。

## Testing Decisions

好测试只测外部行为：通过 HTTP 接口和页面上用户能看到、能点的东西断言，不测组件内部状态、不对快照逐字比对。三个边界：

- **`helmd` HTTP 接口**（现有边界）：用临时数据目录和假驱动起真实 `helmd`，测新增和补充的读取字段（标题取首行、收件箱字段、项目 git 状态、模板使用情况、`list-rounds`、`get-round-output`、`send-message` 的 `cardId`），以及静态托管（文件返回、未知路径回落 `index.html`、路径穿越被拒、POST 接口不受影响）。先例：`tests/helmd.test.ts`、`tests/helmd-fixture.ts`、`tests/user-operations.test.ts`、`tests/output-management.test.ts`。
- **界面整体**（新边界）：Vitest + jsdom 渲染整个应用，连接用假驱动起的真实 `helmd`（复用 helmd fixture），按用户故事操作页面，断言页面显示的内容和 `helmd` 的状态变化：新建工作并进入对齐中、确认工作说明、收件箱分组和行内决定关卡、发消息带范围、打断轮次、审核接受 / 退回、暂停 / 取消（含二次确认）、SSE 推送后页面更新、断线重连补齐、操作被拒时显示原因、模板保存与冲突。不在 jsdom 里测布局坐标和视觉。在沙箱内随 `npm test` 运行。
- **真实冒烟**：沿用 `npm run test:real`，在沙箱外用 Playwright 自带的 Chrome for Testing 有界面模式打开 `helm serve` 的界面，走一遍新建工作 → 对齐 → 执行 → 审核，截图存证；验收时人工看截图，对照设计稿检查布局和状态。浏览器只按 `~/.claude/CLAUDE.md` 和 AGENTS.md 的规则启动，沙箱内不起真实浏览器。先例：`tests/real-smoke-runner.ts`、`tests/browser.real.ts`。

## Out of Scope

- 系统通知、推送到手机（ntfy、飞书等），沿用 [15](../helm-v1/issues/15-v1-slice.md) 的结论。
- 远程访问和认证：v1 只监听本机，服务器上用 SSH 端口转发看界面。
- 删除 Agent 模板，在界面编辑 `skills/` 和 API 模板的主目录内容。
