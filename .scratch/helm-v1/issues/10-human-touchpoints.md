# 人的介入：提需求、中途改卡片图、审核

Type: grilling
Status: open
Labels: wayfinder:grilling
Blocked by: 05, 07
Map: [Helm v1 设计](../map.md)

## Question

用户以什么形式对齐需求、边界和标准？用户中途修改卡片图或卡片时，正在运行的任务怎么处理，调度者怎么得知？哪些情况需要停下来等用户决定（决策关卡）？最后的审核看什么、能做哪些操作（通过、打回、逐行批注）？

## Comments

- 来自 01（2026-10-21）已定：用户只通过消息提出修改，由调度者判断冲突程度：不冲突就立即改；冲突但能等，就记成待办，等受影响的派单结束后再改；冲突太大，就暂停受影响的卡片并加决策关卡。暂停和取消由用户在界面上直接操作，运行层立即执行。用户确认工作说明后，卡片图不需要批准就开始执行。审核是每项工作最后一个决策关卡。

- 来自 [05](05-task-store-model.md)（2026-10-21）：用户与调度者的交互统一为每项工作一条对话（消息 + 决策关卡按时间穿插）。确认工作说明、审核是固定关卡；审核关卡的正文即汇总报告，选项为接受 / 退回，退回后调度者再发起新的审核关卡。工作说明修改走"新版本 + 确认关卡"。逐行批注等更细的审核操作仍由本单定。
