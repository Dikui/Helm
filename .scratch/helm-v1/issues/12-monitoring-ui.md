## Question

界面长什么样：怎样一眼看到每项工作、每张卡片的状态、谁在做、做到哪一步？怎样回放一个任务的过程、追溯问题，怎样完成审核？用 `/prototype` 或 `/mockup` 做粗略稿，链接到本任务单。

## Comments

- 来自 [05](05-task-store-model.md)（2026-10-21）：用户与调度者的交互统一为每项工作一条对话流；决策关卡（含确认工作说明、审核）在对话中显示为带选项的卡片，同时是卡片图上的节点。"等待用户"只来自未关闭的决策关卡，界面需要一种提醒用户有待处理交互的方式（与地图"待明确"中的通知一并考虑）。

- 2026-10-22 来自 [10](10-human-touchpoints.md)：审核界面在汇总报告旁边固定附上工作分支相对基准 ref 的 diff、整体验收的结论、被拒绝的操作数和未声明结论的派单数，从卡片能追到派单和派单输出的步骤；审核只有接受 / 退回 + 意见，不做逐行批注。用户能直接做的操作只有：暂停 / 恢复 / 取消卡片和工作、对关卡作决定、打断轮次、发消息、换调度者模板。确认工作说明关卡同时展示基准 ref 和未提交改动提醒。

- 2026-10-22 来自 [11](11-persistence-and-recovery.md)：① `~/.helm/` 下输出总量超过 10 GB（可调）时提示一次。② 已结束的工作提供"导出"（一个 `.tar.gz`：全部输出文件加该工作在任务库里的记录 JSON，用户选存放位置）和"删除输出"；删除前提示先导出。删除后派单、事件仍可看，输出处显示"已删除"。③ 被中止原因多了"运行层重启"。
- 2026-10-22 来自 [11](11-persistence-and-recovery.md)：helmd 启动时会杀掉工作目录在 `~/.helm/worktrees/` 下的所有进程，包括用户自己停在副本目录里的终端。界面在显示副本路径的地方提示"别在副本目录里开终端，看代码去工作分支"。

## Answer

2026-10-22 grilling 定稿。用户之后自己设计前端，本单只定界面的必须项（必须能看到、能做什么），不画稿，布局、样式、设备与语言都留给前端设计。

**必须项**
1. 工作列表：每项工作的状态、有没有待用户决定的关卡。
2. 对话：消息和关卡按时间穿插；用户能发消息（可注明卡片或关卡），对关卡选选项或自由回答。
3. 卡片图：每张卡片的状态、执行者模板、做到哪一步（当前步骤号 + 最新一步的一行摘要，实时，取自派单输出）；依赖和关卡节点。
4. 派单：每张卡片的全部派单；派单结果（结束方式，被中止注明原因；自报结论及理由；最终回答）；派单输出按步骤查看；卡片的成果（分支、文件、测试输出）。
5. 调度者：当前轮次状态（运行中 / 空闲 / 连败暂停）；每个调度轮次及其输出；调度笔记各版本。
6. 确认工作说明关卡：工作说明、基准 ref、未提交改动提醒。
7. 审核：汇总报告、工作分支相对基准 ref 的 diff、整体验收结论、被拒绝的操作数、未声明结论的派单数；只有接受 / 退回 + 意见。
8. 用户操作：暂停 / 恢复 / 取消卡片和工作、打断轮次、换调度者模板；不提供标完成和派单。
9. 全局：执行者并发数 / 上限、排队数。
10. 输出管理：超过 10 GB 提示；已结束的工作可导出、可删除输出，删除前提示导出，删除后显示"已删除"；显示副本路径处提示别在副本目录开终端。
11. 设置：项目登记、Agent 模板、并发上限、输出提示阈值。
12. 实时：状态变化经 SSE 推送，不用手动刷新。

**追溯**：每项工作一条事件时间线，可按卡片、派单、执行方（用户 / 调度轮次 / 派单 / 运行层）筛选，点事件跳到对应的派单输出步骤。不做重现某时刻卡片图的回放播放器。

**提醒**：本单只要求界面内能看出有待决定的关卡；系统通知、飞书等仍在地图"待明确"中。

**前端设计**：作为前端开发待办，开发界面的任务单依赖它；在 [15](15-v1-slice.md) 切分时列为前置条件。
