## Question

界面长什么样：怎样一眼看到每项工作、每张卡片的状态、谁在做、做到哪一步？怎样回放一个任务的过程、追溯问题，怎样完成审核？用 `/prototype` 或 `/mockup` 做粗略稿，链接到本任务单。

## Comments

- 来自 [05](05-task-store-model.md)（2026-10-21）：用户与调度者的交互统一为每项工作一条对话流；决策关卡（含确认工作说明、审核）在对话中显示为带选项的卡片，同时是卡片图上的节点。"等待用户"只来自未关闭的决策关卡，界面需要一种提醒用户有待处理交互的方式（与地图"待明确"中的通知一并考虑）。

- 2026-10-22 来自 [10](10-human-touchpoints.md)：审核界面在汇总报告旁边固定附上工作分支相对基准 ref 的 diff、整体验收的结论、被拒绝的操作数和未声明结论的派单数，从卡片能追到派单和派单输出的步骤；审核只有接受 / 退回 + 意见，不做逐行批注。用户能直接做的操作只有：暂停 / 恢复 / 取消卡片和工作、对关卡作决定、打断轮次、发消息、换调度者模板。确认工作说明关卡同时展示基准 ref 和未提交改动提醒。

- 2026-10-22 来自 [11](11-persistence-and-recovery.md)：① `~/.helm/` 下输出总量超过 10 GB（可调）时提示一次。② 已结束的工作提供"导出"（一个 `.tar.gz`：全部输出文件加该工作在任务库里的记录 JSON，用户选存放位置）和"删除输出"；删除前提示先导出。删除后派单、事件仍可看，输出处显示"已删除"。③ 被中止原因多了"运行层重启"。
