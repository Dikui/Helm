# 12 — 启动对账

**What to build:** `helmd` 在任何时刻崩溃或被停止后再启动，都会先清掉残留进程、再收拾 git 状态，把任务库与实际状态对齐：运行中的派单交调度者决定续跑，轮次重投，半截的合并被 abort，缺失的合并与推送被补做，残留的副本被删除。见 [spec](../spec.md) 的"启动对账"。

**Blocked by:** 05 — 派单的并发、看门狗和副本清理；08 — 浏览器派单；09 — 审核与合进基准分支；10 — 用户的直接操作；11 — 调度轮次失败、额度用完与 token 汇总

**Status:** ready-for-agent

- [ ] 先杀进程再动 git：工作目录在副本根目录下的进程连同进程组先 `SIGTERM` 后 `SIGKILL`；库里记的 Playwright MCP 进程组仍存活且启动时间对得上的杀整组、回收端口段
- [ ] 运行中的派单记"被中止：运行层重启"并唤醒调度者；运行中的执行派单补提交，提交信息写结束方式
- [ ] 运行中的轮次记结束（运行层重启），事件重投，不计入连续失败
- [ ] `_work` 半截合并 `merge --abort`；项目目录留有 helmd 发起、指向工作分支的 `MERGE_HEAD` 时先 abort
- [ ] 已完成但缺合并或推送结果事件的工作补做；基准分支已包含工作分支就跳过合并
- [ ] 补删终态卡片残留的 worktree 和卡片分支、已结束工作残留的 `_work`
- [ ] 排队中的派单保持排队，未处理的唤醒事件照常投递，已暂停的工作保持暂停
- [ ] 测试在各中间状态（派单运行中、标完成合并到一半、审核接受后推送前、终态卡片未删副本）杀掉 `helmd` 再启动，断言恢复后的状态
