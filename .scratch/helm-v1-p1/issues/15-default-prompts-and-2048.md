# 15 — 默认提示词与 2048 端到端

**What to build:** 写好默认的调度者和执行者提示词，用真实 Claude 驱动从对齐到审核接受跑完一次网页版 2048，含浏览器验收，证明第一版的完整流程能走通。见 [spec](../spec.md) 的"默认调度者提示词"和"Testing Decisions"端到端验收。

**Blocked by:** 09 — 审核与合进基准分支；11 — 调度轮次失败、额度用完与 token 汇总；12 — 启动对账；14 — Claude 调度者驱动

**Status:** ready-for-agent

- [ ] 调度者提示词写明 spec 列出的各项（整体验收卡片、验收通过后不再派执行单、冲突建修复卡片、交叉验收建议、验收卡片写清边界和标准、额度用完改派或提关卡、关卡参考情形且尽量少提、汇总报告格式、调度笔记约 4k token、不推送不部署）
- [ ] 执行者提示词写明不推送不部署、开发服务用分配的端口、检查过程和证据写进最终回答、最后调用"提交结论"
- [ ] 用 `helm` 命令行在一个空仓库上发起 2048 工作，期望拆成 4～5 张有依赖的卡片；经确认关卡、执行与验收派单（含浏览器验收）、整体验收、审核接受，基准分支含可玩的 2048 并推送到本地远端
- [ ] 用消耗小的模型和低推理强度；浏览器检查不在沙箱里跑，验收时查看截图
- [ ] 合并冲突不强求；出现了就检查修复卡片流程
- [ ] 报告附事件时间线摘要：每张卡片由谁完成、验收结果、token 汇总，以及暴露的问题
