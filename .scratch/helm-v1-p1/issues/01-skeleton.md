# 01 — 骨架：登记项目并开始一项工作

**What to build:** 用户用 `helm serve` 起 `helmd`，用 `helm` 命令行登记一个本机 git 仓库为项目、设全局并发上限，选项目发第一条消息就新建一项工作（对齐中），运行层同时生成"确认工作说明"关卡。用户能读对话（消息和关卡按时间穿插）、读事件时间线（可按卡片、派单、执行方筛选），SSE 实时推送状态变化，待处理事项接口列出这个关卡并推送"需要用户处理"事件。HTTP 路由、MCP 工具和 `helm` 子命令都由同一份操作定义生成，共用约束检查。见 [spec](../spec.md) 的"进程与存储""操作定义与对外接口"。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] `helmd` 只监听 `127.0.0.1`，数据目录可配置（测试用临时目录，默认 `~/.helm/`），任务库用 `node:sqlite` WAL
- [x] 每次操作在同一事务里改状态行、追加事件；事件记时间、执行方、对象、动作、细节
- [x] 每个操作只定义一次（名称、参数 schema、调用方、是否带 `key`），HTTP 路由、MCP 工具、`helm` 子命令由它生成
- [x] 登记项目时校验是 git 仓库；发第一条消息新建工作并生成固定的确认关卡，该关卡不能撤回
- [x] 违反约束时返回结构化错误（错误码、原因、当前允许的操作），并记一条"操作被拒绝"事件
- [x] 待处理事项接口列出待决定的关卡；出现新事项时 SSE 推送"需要用户处理"
- [x] 测试在主边界上：测试里起真的 `helmd`，经 HTTP + SSE 断言，`helm` 命令行有一条冒烟

## Comments
