# 11 — 调度轮次失败、额度用完与 token 汇总

**What to build:** 调度轮次失败会自动重投，连续失败 3 次或调度者自己额度用完时，运行层暂停工作、列入待处理事项，由用户手动恢复。执行者额度用完时派单以"额度用完"结束，交调度者改派。每次派单和调度轮次的 token 用量汇总到卡片和工作。见 [spec](../spec.md) 的"调度轮次"和用户故事 26、51。

**Blocked by:** 04 — 执行派单主路径

**Status:** resolved

- [x] 调度轮次看门狗：总时长默认 30 分钟、无输出 10 分钟，可调；轮次结束后清理 `_work` 里的残留进程
- [x] 轮次失败（崩溃、出错退出、超时、上下文溢出）就开新一轮重投，附"上一轮中断，期间已做的操作见任务库"；测试覆盖重投时靠 `key` 不重复建卡和派单
- [x] 连续失败 3 次暂停工作，在对话里发运行层消息，记下暂停原因
- [x] 轮次以额度用完结束时直接暂停工作，不重投
- [x] 被运行层暂停的工作列入待处理事项，推送"需要用户处理"，工作列表标出原因；用户手动恢复
- [x] 执行者派单以"额度用完"结束并唤醒调度者
- [x] 驱动的压缩通知记一条事件，挂在该派单或轮次下
- [x] token 用量按派单和调度轮次记录，可读卡片和工作的汇总
