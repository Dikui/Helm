# 04 — 执行派单主路径

**What to build:** 调度者给待派单的卡片派执行单，`helmd` 在这张卡片第一次派单时从工作分支末端开出卡片副本，用假执行者跑完。执行者经派单令牌调用"提交结论"；派单输出按步骤保存，卡片显示实时步骤；派单结束后 `helmd` 把改动提交到卡片分支并唤醒调度者，调度者和用户都能读派单结果。见 [spec](../spec.md) 的"执行派单"。

**Blocked by:** 03 — 卡片图与决策关卡

**Status:** ready-for-agent

- [ ] 卡片副本在 `~/.helm/worktrees/<工作>/<卡片>`（随数据目录），分支 `helm-card/<工作>/<卡片>`，同一卡片后续派单复用
- [ ] 派单带 `key` 去重；卡片等待前置、已暂停、已完成、已取消或已有运行中/排队中派单时拒绝；工作对齐中、已暂停、已取消时拒绝
- [ ] 执行者模板只能从登记的执行者模板里选；第一版内置 Claude 调度者、Claude 执行者两个模板，只能设模型和推理强度
- [ ] 派单令牌只能用"提交结论"：执行派单可选完成 / 受阻，附一句理由；可多次调用以最后一次为准；没调用记未声明；只有正常完成时结论有效
- [ ] 派单输出按步骤序号存成库外文件，可按步骤读；卡片显示当前步骤号和最新一步的一行摘要，经 SSE 实时更新
- [ ] 派单结果记结束方式、最终回答（仅正常完成）、自报结论及理由、token 用量；结束时唤醒调度者
- [ ] 执行派单结束后提交剩余改动，提交信息写派单 id 和结束方式；成果（分支、文件、测试输出）可读
- [ ] 支持续跑本卡片以前的执行者对话（须用回原模板和会话 id），同一会话 id 不能同时被两次派单续跑；调度者可撤销派单并写原因（结束方式为被中止）
- [ ] 执行者环境用 `GIT_CONFIG_*` 的 `pushInsteadOf` 覆盖 `git@`、`https://`、`ssh://`，并给无效 `GH_TOKEN`：测试中推送到本地远端失败
- [ ] 子进程环境按模板管理，清掉会压过订阅的 key
