# 06 — 标记完成、合并与修复卡片

**What to build:** 调度者标记卡片完成时，`helmd` 在 `_work` 把卡片分支 `--no-ff` 合进工作分支，合并成功才算完成；冲突时拒绝、卡片状态不变。调度者建修复卡片解决冲突后，再标原卡片完成即成功。卡片进入终态时删除它的副本和卡片分支。见 [spec](../spec.md) 的"合并"。

**Blocked by:** 04 — 执行派单主路径

**Status:** ready-for-agent

- [ ] 从没正常完成过任何派单的卡片标不了完成，只能取消
- [ ] 标完成时先合并后写库；重复调用结果不变（合并为"已是最新"）
- [ ] 冲突时中止合并，返回"与工作分支冲突"结构化错误，`_work` 干净
- [ ] 修复卡片记"修复自"；它的副本从工作分支末端开出，把原卡片分支合进来解决冲突；完成后原卡片标完成直接成功
- [ ] 下游卡片的副本从已含上游成果的工作分支开出
- [ ] 卡片完成或取消后删除 worktree 和卡片分支；已取消卡片的提交随之丢弃，事件和派单输出保留；已完成卡片的分支成果指向工作分支上的合并提交
- [ ] 测试用假驱动造出两张卡片改同一文件的冲突，走完修复卡片流程
