# 02 — 对齐：调度轮次与假驱动

**What to build:** 用户发消息或决定关卡后，`helmd` 用假驱动开一个调度轮次：拼启动简报、发只能操作本工作的轮次令牌。调度者经 MCP 起草工作说明、发消息、改写调度笔记；用户确认工作说明后，`helmd` 从基准 ref 开出工作分支 `helm/<工作>` 和 `_work`，工作进入执行中。这一单同时定下驱动接口，并提供按脚本回放的假驱动。见 [spec](../spec.md) 的"驱动接口""调度轮次"。

**Blocked by:** 01 — 骨架：登记项目并开始一项工作

**Status:** resolved

- [x] 驱动接口覆盖：按 cwd、环境变量、沙箱设置、注入的 MCP 拉起会话（新开或续跑），送入内容、取消、逐条交回带步骤序号的输出、压缩通知、结束消息、结束方式、token 用量
- [x] 假驱动按脚本回放：可调用真实 MCP 端点上的工具、写文件、产生步骤输出、以指定结束方式结束、挂住、崩溃
- [x] 唤醒事件进入工作队列，没有轮次在跑时合成一轮投递；同一工作同时最多一个轮次；轮次正常结束后事件才标为已处理
- [x] 启动简报含工作说明（草稿标"未确认"）、卡片图摘要、未决关卡、调度笔记全文、上一轮以来的新事件、最近 20 条对话
- [x] 轮次令牌只能操作所属工作，轮次结束即失效
- [x] 新建类工具（起草工作说明版本、发消息等）带 `key`，重复调用返回已有对象
- [x] 确认关卡展示工作说明、基准 ref（默认当前分支 HEAD）和未提交改动提醒；确认后开出工作分支和 `_work`
- [x] 确认后再起草工作说明会自动提新的确认关卡，确认后新版本生效、旧版本被取代
- [x] 调度笔记每轮可整份改写，每个版本记一条事件
