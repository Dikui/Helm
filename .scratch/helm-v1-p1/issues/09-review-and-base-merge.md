# 09 — 审核与合进基准分支

**What to build:** 调度者发起审核，正文就是汇总报告；用户看到报告和运行层固定附上的 diff、整体验收结论、被拒绝的操作数、未声明结论的派单数，只能接受或退回。退回后调度者处理完重新发起审核；接受后 `helmd` 预检、无冲突才合进基准分支并推送，工作进入已完成。见 [spec](../spec.md) 的"合并"和用户故事 44–48。

**Blocked by:** 07 — 验收派单

**Status:** ready-for-agent

- [ ] 审核关卡是固定关卡，可选项只有接受 / 退回，退回时可写意见；发起审核带 `key` 去重
- [ ] 审核关卡旁可读：工作分支相对基准 ref 的 diff、整体验收结论、被拒绝的操作数、未声明结论的派单数
- [ ] 工作有未关闭的审核关卡时为待审核，并推送"需要用户处理"；退回后回到执行中，旧关卡保留
- [ ] 审核关卡被接受前工作不能完成
- [ ] 接受后先 `git merge-tree --write-tree` 预检；有冲突不合并，在对话里报告冲突文件和工作分支名
- [ ] 无冲突时：基准分支未在项目目录检出用 `commit-tree` + `update-ref`；已检出就在项目目录 `merge --no-ff`，git 拒绝时只报告
- [ ] 然后推送基准分支（测试用本地 bare 仓库作远端）；冲突或推送失败不重试，结果记事件
- [ ] 不论成败工作进入已完成，删除 `_work`，工作分支保留，之后不再唤醒调度者
