# 03 — 卡片图与决策关卡

**What to build:** 调度者在执行中的工作里建卡片、改卡片、设置或取消"需要验收"、加删依赖，提出、修改、撤回一般决策关卡；用户对关卡作决定后，后面的卡片解除阻塞。用户能读卡片图：每张卡片的状态、依赖和关卡节点。见 [spec](../spec.md) 的"实体与状态""硬约束"。

**Blocked by:** 02 — 对齐：调度轮次与假驱动

**Status:** resolved

- [x] 建卡片、提关卡带 `key` 去重；改卡片内容在终态以外随时可改，并记事件
- [x] 卡片状态由依赖推导：等待前置 / 待派单；卡片变为待派单时唤醒调度者
- [x] 拒绝成环、跨工作、上游为已取消卡片或已撤回关卡的边；完成、已取消的卡片不能再加依赖
- [x] 删依赖后前置都满足的下游自动变为待派单
- [x] 上游被取消或撤回时下游保持阻塞并唤醒调度者，不自动放行、不连锁取消
- [x] 只有用户的决定能关闭关卡；用户可选选项或写自由回答；调度者能撤回自己提的一般关卡，不能撤回固定关卡
- [x] 关卡问题和正文的每次修改记成事件，可读修改历史

## Comments

实现按 key 去重的卡片与一般关卡、卡片内容及验收标记修改、依赖约束与状态推导、取消或撤回后的阻塞和唤醒、用户决定及关卡修改历史，并通过真实 HTTP/MCP、假驱动与重启集成测试验证。
