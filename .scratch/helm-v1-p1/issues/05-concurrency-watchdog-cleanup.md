# 05 — 派单的并发、看门狗和副本清理

**What to build:** 派单受全局并发上限约束，满了就排队，用户能看到并发数、上限和排队数；每次派单分配一段本机端口。看门狗杀掉挂死的执行者。不论派单怎样结束，副本里的残留进程都会被清掉，再收拾 git 状态并提交；派单开始前副本不干净就先重置。见 [spec](../spec.md) 的"执行派单"。

**Blocked by:** 04 — 执行派单主路径

**Status:** resolved

- [x] 并发只计执行者派单（执行和验收都算），默认 10，用户可调；满了排队、不拒绝，有空位时按序拉起
- [x] 每次派单分配一段不重叠的本机端口，经环境变量传给执行者，派单结束回收
- [x] 看门狗按墙钟总时长和无输出时长两个可调阈值杀进程组，结束方式记为超时终止
- [x] 任何结束方式之后，按工作目录找到副本里的进程连同进程组，先 `SIGTERM`，5 秒后仍存活的 `SIGKILL`，再处理 git
- [x] 提交前删残留 `index.lock`，abort 进行中的 merge、rebase、cherry-pick、revert 并记事件；测试覆盖"合并到一半""rebase 到一半"不会把冲突标记或游离 HEAD 提交上去
- [x] 测试覆盖执行者用 `nohup … &` 留下的后台进程在派单结束后被清掉
- [x] 派单开始前副本 `git status` 不干净（被 ignore 的不算）时，记事件列出被改文件并重置到卡片分支 HEAD
- [x] 派单和 Helm 拉起的进程记下 pgid 与启动时间
