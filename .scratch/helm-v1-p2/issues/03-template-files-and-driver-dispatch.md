# 03 — 模板文件化与按驱动分派

**What to build:** 用户在 Helm 仓库的模板目录里用文件定义 Agent 模板（先内置 `claude-coordinator`、`claude-executor`），改了文件下一次派单或调度轮次就生效，不用改代码或重启。提示词文件只放策略，运行层约定由代码拼在后面。派单和调度轮次都留一份模板快照。`helmd` 按模板的驱动字段选驱动，为后面接 Codex 打底。见 [spec](../spec.md) 的"模板以文件为准""驱动按模板分派"。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 模板目录每个模板一个目录（设置文件、`prompt.md`、可选 `skills/`），id 即目录名；设置字段：角色、驱动、模型、推理强度、fast、主目录、职责说明
- [ ] 每个调度轮次、每次派单开始时读取模板；改文件后下一次即生效，`helmd` 不重启
- [ ] 派单和调度轮次都存解析后的模板快照，用户和调度者能读到
- [ ] 去掉库里的模板表和 `configure-agent-template` 操作，卡片和派单对模板 id 的外键去掉；迁移保留已有派单的快照
- [ ] 默认提示词拆开：策略进内置模板的 `prompt.md`，端口段、提交结论、进程清理、截图路径、不推送、验收前附卡片说明快照等运行层约定留在代码里拼接；拆分后第一版的行为不变
- [ ] `list-agent-templates` 返回 id、角色、驱动、模型、职责说明、计费方式（订阅 / API）、是否可用及原因
- [ ] 解析失败或 id 不存在的模板不可用，不影响其他模板；派单和调度轮次用到它时返回结构化错误
- [ ] 设了 fast 的 Claude 模板不可用，原因写明 Claude fast 在订阅下要开 extra usage 并计入 extra usage
- [ ] `helmd` 按驱动名登记驱动，派单和调度轮次按模板的驱动字段选；测试按驱动名注入假驱动，断言派单进了对应驱动
- [ ] 主边界测试覆盖以上行为；`npm run check`、`npm test` 通过
